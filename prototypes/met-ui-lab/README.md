# MET Wild Web · 首段星图与技术贸易

这是 MET「来生」的独立网页交互原型，用于讨论现代策略 HUD、管理工作台、来源追踪与操作流程。它使用 React、TypeScript 和自包含演示模型，不连接 Unity 或 Godot，不读取正式玩家存档。

当前目标展示基线为桌面全屏、2560×1440（2K）。早期 V1—V3 的 1920×1080 记录保留历史含义。地图缩放、界面比例与文字大小分别控制；此原型不承担移动端适配任务。

## 2026-10-26：Wild 首段可操作版本

点击地图农居，在地块面板选择「进入 Wild 建筑星图」。首次进入获得 2 件低级工业品；普通节点、路线、施工、希望城技术购买与农居 T2 进阶均使用同一份状态。以后从「建筑星图」继续。

- [试玩路线](docs/WILD-PLAY.md)：贸易取得住房设计 → 两种农居进阶 → 观察容量与资源变化。
- [已确认规则和待定边界](docs/WEB-RULES.md)、[经济基底](docs/ECONOMY-BASIS.md)。
- [工程检查](docs/WILD-CHECKS.md)：79 项自动化检查、离线 2K 浏览器操作与截图；不代替用户验收。

本版仍是逐步接入的可操作片段。学校和作坊后续星图、T3 工业品配方、后续科技、Wild Bonus 实装与模板尚未完成；其余经营数据仍包含原 UI demo 夹具，不能视作已确认的新经济或数值平衡。街区月份仍通过「＋月」推进，城市科研使用独立现实时间时钟。

离线版本与 ZIP 位于 `delivery/MET-Wild-Web-star-01/` 和同名 ZIP。旧 V1—V3 包保留。源码位于本目录 `src`，新规则位于 `src/game`。Wild 支持独立手动／自动存档及 JSON 导入导出，恢复时街区暂停、科研补算离线时间。

## V3 的变化

地块信息固定在地图左下角，和全局工作区分开。容量占用采用进度条加数字，资源贡献使用共用零轴的正负条形图。任务以目标进度组织，Bonus 库存使用图标槽位式选项。交易、政策对比和高级详表仍保留适合核对的表格。

详见 [V3-GRAPHICS.md](docs/V3-GRAPHICS.md)。`delivery/MET-UI-Lab-v3/index.html` 是可独立打开的单文件，ZIP 内含相同页面、源码与说明；V1、V2 原包均保留。

## V2 的变化

日常入口改为地图旁的小表：居民、资源与财政、施工、任务、Bonus 均能直接操作。上一版的大表保留为高级详表，右上「详表」展开，「收回侧栏」或 Esc 返回。档案继续直接使用完整页。V1 离线包保留在 delivery/MET-UI-Lab-v1/。

设计分工与体验路线见 [V2-SIDEBARS.md](docs/V2-SIDEBARS.md)。

## 直接打开离线版本

完成构建后，打开 `dist/index.html` 即可使用，无需启动开发服务器。macOS 可在本目录运行：

```sh
open dist/index.html
```

构建过程先检查 TypeScript，再由 Vite 打包，最后把脚本、样式及地图图片内联到 HTML。分发时可提供构建后的这一个 HTML 文件。`dist` 是生成物，修改功能应编辑 `src` 后重新构建。

演示状态可在「MET · 系统」保存到当前浏览器的本地存储。它不是正式游戏存档，也不是跨浏览器同步；离线文件与开发服务器可能属于不同存储环境。浏览器不允许本地存储时，界面会提示保存失败，仍可继续体验。

## 开发与检查

需要本机 Node.js 与 npm。首次安装及日常命令：

```sh
npm install
npm run dev
npm test
npm run build
```

开发服务器绑定 `127.0.0.1`，打开终端显示的本地地址。`npm run preview` 可预览已构建版本；`npm test` 运行模型与服务端组件渲染测试，`npm run build` 包含类型检查和离线 HTML 生成。

模型测试覆盖资源、交易、施工、临时队、Bonus、阶段奖励、主题、期限和只读限制。类型检查或模型测试通过，只证明各自检查范围；浏览器画面、真实键鼠操作与用户验收需要另外记录。本轮工程检查记录见 [CHECKS.md](docs/CHECKS.md)，最终视觉与操作体验由用户验收。

## 从哪里开始

默认打开「平稳经营」地图，并在左下角选中邻里中心。左侧固定导航进入日常小表，点击地图地块查看局部建筑，右下「＋月」执行一次演示月结算。时间初始暂停，需先点击继续；仅切换倍速不会自动推进月份。

- [六组场景实操](docs/SCENARIOS.md)：首次开拓、日常经营、短缺、施工、奖励，以及终局／只读子变体。
- [界面结构与数据口径](docs/DESIGN.md)：导航、抽屉、操作窗、共用组件与视觉 tokens。
- [Unity 后续映射](docs/UNITY_MAPPING.md)：后续移植时需要对接的视图、命令、快照和验收项。本轮没有执行移植。

## 代码与素材来源

`src/App.tsx` 组织 HUD、地图、抽屉与操作窗；`src/compact` 是日常图形侧栏；`src/panels` 保留完整管理工作区；`src/model.ts` 提供演示夹具、派生汇总和纯命令；`src/types.ts` 定义共享接口。`src/ui.tsx` 与样式文件提供共用组件。

地图底图 `src/city-background.png` 取自本项目已有的 [city-hillside-buildings.png](../../docs/ui_planning/evidence/ui6/city-hillside-buildings.png)，来源边界见 [UI6 验收记录](../../docs/ui_planning/UI6_ACCEPTANCE.md)。原图是既有 Unity 坡地展示 fixture 的 Player 画面：真实生成地形上注入目录建筑位置／占用，用于展示地形、建筑支撑与入口；它不代表正常游玩进度或建造资格。本原型只把该画面作为静态背景，叠加可交互 SVG 地块与建筑符号，未实时渲染原场景。

历史 UI demo 的人口、价格、流量、条件、委托和奖励为演示数据；Wild 中已确认并接入的部分以 WEB-RULES.md 为准，其余尚未迁移。名称与流程服务于 MET 讨论，但这里的参数不证明正式游戏的数值平衡、经济可行性或已完成的 Unity 功能。旧截图及其历史验收也不构成本原型的新验收。
