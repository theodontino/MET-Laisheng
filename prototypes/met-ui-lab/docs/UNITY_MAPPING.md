# Unity 后续迁移映射

本轮交付的是独立网页交互原型，未把这些组件、夹具或状态写入 Unity。下面是后续实施清单，属于待做的对接工作，不是已经完成的移植或授权扩大玩法范围。

迁移应继续同一 MET Beta 游戏，遵循仓库现有 UI 合同和 Unity 全迁移边界。网页模型仅提供流程示意；正式规则、来源记录、单位与权限应以实际模拟和已批准设计为准。

## 视图与交互对应

| 网页结构 | 后续 Unity 对应方向 |
| --- | --- |
| `App` 固定 HUD、资源条、左导航 | 现有 uGUI Canvas 下的持久外壳，绑定统一只读城市快照 |
| `WorldMap`、图层与选中地块 | 现有城市相机、地块选择与图层展示；使用引擎坐标和实体 ID |
| 局部地块卡、来源抽屉 | 共用建筑详情视图，保留运营方、提供方、槽位和来源身份 |
| 七个管理工作区 | 常驻外壳内的内容面板；分别管理页签、筛选、排序和滚动恢复 |
| `OperationModal`、行内确认 | 独立操作层，承接方案选择、费用、约束、比较与最终命令 |
| `ui.tsx` 共用组件与 CSS tokens | uGUI 预制体、主题资源、字体／图标资源及明确视觉状态 |
| 档案记录、来源行 | 正式事件／结算／成就／规则记录的读取适配器 |
| 本地演示保存 | 仅作网页实验存储；Unity 使用自身正式保存服务与目录 |

静态网页底图不能替代 Unity 的动态城市表现。已有坡地截图保留历史来源含义；真正的地图交互必须对应实际相机、实体、地块与建筑，不把网页六边形坐标直接当作引擎坐标。

## 快照与命令适配

- 建立一份 UI 快照读取层，统一提供库存、经营预估、实际回执、人口、住房、岗位、服务容量与满足、施工、电力和环境数据。网页 `GameState` 不能直接替代正式模拟状态。
- 将 `effectiveBuilding`、`summary`、`tileFacts` 和 `conditions` 的用途映射到现有正式查询；避免在多个面板重新实现同一规则。正式服务分配、就业与地理算法仍由正式系统负责。
- 为新建、升级、开停、施工优先级、招募、交易、政策、移民、消费、委托、奖励、Bonus、阶段和终局操作建立命令入口。确认时重新读取正式资格、费用和资源，成功后发布新的 UI 快照与记录。
- 预览读取脱离状态的同一步基线／方案快照，保留库存、月流、供电容量和环境口径。不要为了画预览改变玩家钱包、实体、模拟时间或 RNG。
- 用正式 ID 关联住区、供应者、运营者、槽位、订单、工程与记录，支持「来源详情 → 地图定位 → 返回原列表」。可用库存与预留资源、经营预估与到账回执必须分开。
- 主题目标、委托、Bonus 与专业化使用正式内容目录；网页的五主题和简化数值不能自动写入正式平衡表。

## 输入与状态恢复

需要在引擎侧明确输入层级：文本控件先处理输入，操作窗独占交互，抽屉与工作台拦截底层地图。关闭最上层界面后恢复合理焦点，Tab、Esc、地图快捷键与选择状态应有一致行为。

界面比例 80／100／120%、字体大小和地图缩放保持独立。管理页切换与地图定位保留页签、筛选、排序、选中对象及滚动位置。来源对象不存在、操作资格改变和资源不足时，给出可理解的处理结果；无需照搬网页内部临时状态实现。

## 接入后的验证清单

1. 在 Unity 实际编译、导入并运行目标 macOS Player；全屏基线为 1920×1080，不扩展成其他窗口尺寸或移动端验收。
2. 逐组执行网页场景对应的真实流程，但由正式夹具或实际状态提供数据。首次未结算、短缺、升级、新建、奖励队列、DT 归零和只读历史状态都应覆盖。
3. 使用真实鼠标和键盘检查固定导航、焦点、遮罩、Esc、图层循环、来源抽屉、定位返回及三种独立缩放。程序回调通过不能替代这些检查。
4. 核对比较前后同一步快照、来源 ID、预留库存、历史回执、服务分母、全城环境分母与阶段完成记录，确认展示没有改写正式模拟。
5. 在测量期间固定源码与资源，分别记录模拟成本和渲染帧表现；网页运行或旧 Player 截图不证明新 Unity 性能。
6. 把实际 Player 截图、交互记录、性能与构建结果写入对应的正式验收文档，注明版本、平台和检查范围。只有真实执行结果才能形成新的验收结论。

当前网页模型测试只验证演示命令与派生状态；HTML 构建只验证网页打包。两者都不能代替 Unity 编译、原生启动、动态城市画面或用户验收。


## V2 视图分工补充

本次原型新增 `src/compact/` 日常视图；`src/panels/` 保留高级详表，不复制结算与命令。未来 Unity 移植可在页面描述中增加日常／展开两种 presentation，并分别保留滚动位置，其他选中实体、筛选和草稿共享。`advanced` 只切展示形式，不能把另一栏目压成父页。地图定位返回需同时恢复栏目与展开状态。

`conditionDestination` 把每种目标映射到具体指标，避免“医疗”跳到任意旧服务筛选。Bonus 深链带方案、建筑与槽位，且独立于库存是否大于零。上述是后续迁移建议，本轮没有修改 Unity。


## V3 增量（待未来移植）

地块展示状态独立于全局工作区；布局绑定导航实际下沿和底部占位。地块滚动按地块 ID 恢复。容量控件显式提供 value/max/unit 与超限含义，资源净额图显式提供共同正负刻度；不要把普通产量强行转换成百分比。本轮只在独立网页实现，未移植 Unity。
