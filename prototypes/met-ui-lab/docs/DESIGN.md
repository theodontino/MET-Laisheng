# 界面结构与数据口径

**V2 补充：** 日常小表与高级详表的最新职责见 [V2-SIDEBARS.md](V2-SIDEBARS.md)。以下数据口径继续适用；原「工作区」的大表在 V2 中对应高级详表。小表与详表共用 GameState 与栏目选择，分别保存 `scroll` / `advancedScroll`；从地图定位恢复时还保存展开状态。

本说明描述网页原型的实现边界。它把「看见问题 → 找到来源 → 比较方案 → 明确操作 → 回看记录」串成一条路径，供后续 Unity 实现参考。

## 信息架构与固定区域

城市地图是主画面。顶部资源条提供人口、DT、库存、CP 和电力摘要，点击进入对应管理入口；左侧固定导航按街区经营、发展与能力、城市记忆分组。当前「城市」入口明确锁定，系统入口位于 MET 标志。

管理工作区包括居民与服务、资源与财政、施工、任务与成长、Bonus、档案和系统。工作区在地图上方打开，顶部保留街区上下文，底部标明演示来源；正文单独滚动。地图图层位于底部，时间控制位于右下。没有工作区时，右侧显示当前目标及口粮、医疗、待领取奖励等提示，左下显示选中地块。

各工作区负责一类问题：

- 居民与服务：定位住区缺口，查看服务提供者、就业和供应设置。
- 资源与财政：区分可用库存、经营月流、一次性支付与已发生回执；处理订单与政策。
- 施工：按优先级分配能力，查看材料、电力和临时队限制。
- 任务与成长：查看条件、连续达标月份、主题委托、阶段奖励和终局步骤。
- Bonus：从副本库选能力，再选建筑与槽位，最后比较实际改变。
- 档案：按事件、结算、成就、规则分类，检索并阅读完整记录。
- 系统：显示设置、时间规则、本地演示保存和六组夹具入口。

工作区的页签、筛选、选中项、排序及滚动位置由 `PanelMemory` 按工作区保留。组件内部的临时表单与搜索状态不属于统一的长期保存协议。返回地图不会创建另一份城市；定位后可使用返回入口恢复原列表。

## 来源抽屉、地块卡与操作窗

地图选中地块打开局部卡，说明建筑身份、运营者、等级、当地人口、资源净流、服务、环境、槽位与可执行行动。空地显示地形、特征和建设入口，不展示不存在建筑的实际产出或服务满足。

列表中的来源名称通过 `inspect` 打开同一类建筑详情抽屉，保持原列表可恢复。`locate` 则收起工作区、定位地图，并提供返回原列表的入口。来源抽屉负责查阅与追溯；复杂决策进入独立操作窗。

操作窗包括新建、升级、临时施工队、奖励选择和新演示向导。新建／升级按「选方案 → 比较收益与代价 → 确认开工」组织，主要影响先显示，完整城市对比可展开。选择方案和查看预览不扣款、不推进月份；确认命令成功后才更新城市。

抽屉有遮罩和关闭入口；操作窗有明确标题、取消与确认，打开时聚焦对话框，并限制 Tab 焦点在窗内。`Esc` 根据当前层级收起操作窗、抽屉或工作区；输入控件优先拥有文字键盘输入。地图状态下 `L`／`Shift+L` 切换图层，单独按 Shift 切换数值标签。悬停提示用于摘要和入口说明，不承担唯一的操作路径。

## 共用组件与视觉 tokens

`src/ui.tsx` 的基础组件包括 `Icon`、`Button`、`Tag`、`Stat`、`Progress`、`SectionTitle`、`Tabs`、`Fold`、`Empty`、`Search`、`SourceLine`、`Choice` 和 `InlineConfirm`。图标使用本地 SVG 路径；建筑符号也由 SVG 几何绘制。完整目录和原始记录通过折叠区或档案保留，避免把首页变成长表格。

当前 CSS 根 tokens 如下；具体页面尚有局部样式，后续可归并为统一主题资源。

| 用途 | 当前值 |
| --- | --- |
| 正文 `--ink` | `#e4eae6` |
| 次要文字 `--muted` | `#91a5a4` |
| 强调／正向 `--teal` | `#7bcebd` |
| 提醒／代价 `--gold` | `#dfbb77` |
| 缺口／负向 `--red` | `#e79b88` |
| 分隔线 `--line` | `#344849` |
| 表面／深层 | `#152526`／`#102021` |
| 基础文字 | 系统无衬线字体，根字号 16px；中文优先苹方或微软雅黑 |

表面以深色半透明面板、细边框和 3–6px 圆角为主。常用间距为 8、12、16、24px 附近，按钮通常至少 36px 高，数据使用等宽数字。颜色同时配合短标签、正负号、状态文字和进度条，不只靠颜色区分状态。

UI 比例支持 80／100／120%，文字支持 100／115／130%；地图缩放独立控制。它们是三种不同设置，不能用整体地图缩放替代阅读设置。这里的参数用于桌面全屏基线，不形成小窗口或移动端交付要求。

## 状态、命令与数据来源

`GameState` 是演示状态，包含资源、地块、建筑、施工、队伍、订单、政策、主题、阶段、委托、奖励与记录。`makeScenario` 每次创建独立夹具；`runCommand` 从输入状态复制后执行操作，返回状态、成功标记和中文反馈。失败命令不更新 App 中的城市状态。

派生数据集中计算：

- `effectiveBuilding` 把槽位 Bonus、蓝图等级、停运和升级占用计入建筑有效值。
- `summary` 生成城市汇总、资源净流、服务、施工与电力指标。
- `tileFacts` 提供地块净流和实际服务满足，供地图、住区与来源明细共用。
- `conditions` 从当前状态计算阶段与主题条件；`conditionGap` 同时处理达标下限与污染上限。
- `comparisons`／`bonusComparison` 在同一输入快照上生成静态前后差异，不推进时间。

### 库存与月流

库存指当前可用量。买单创建时预留通货，卖单创建时预留资源，已从可用量扣除；未成交撤单返还。明确推进月份时才模拟成交。固定报价、买卖同价和本地成交均为演示简化。

经营月流包括建筑有效产出、当地居民消费、收入、维护与政策持续影响。建设耗材、订单预留、招募费、研究费和政策一次性费用不并入经营月流。当地来源行包含该处居民的口粮、可选制成品消费和税收；政策单独列示。因此，当前经营预估与历史到账回执需要分开阅读。

### 服务、就业与环境

建筑 `services` 是有效供应容量，不是百分比。每处住区的实际满足取「全城容量／居民数（含政策调整）」与当地可达度的较小值；城市服务满足再按居民人数加权。空地可有理论可达度，但没有居民实际满足，不能冒充已获得服务。

人口、就业、岗位、已填岗位和居住容量分别展示；就业不会超过对应居民或岗位。升级减少住房时保留原有居民，因此可能形成超容，不能通过删除居民把界面变成看似正常。

污染与余热的全城平均按全部城市地块取分母，含空地；不能只对有建筑地块求平均。图层、服务连线和底图用于演示空间阅读，不证明正式寻路、就业通勤或服务分配算法已经完成。

### 施工、时间与资格

施工原始能力来自基础、建筑和临时队，再乘供电满足比例；预计使用量还受队列、暂停、优先级和可用材料限制。城市工程预留在夹具中为零。材料随施工进度消耗；新建完工前无产出，升级期间原建筑按 65% 运营。T2 次要能力减半、T3 对应次要能力可为零，副本和蓝图效果仍按模型规则计算。

演示不自动走时。单次推进结算一个月，1 倍速不消耗 DT，2 倍速消耗 1 DT，4 倍速消耗 3 DT。DT 归零后仍可 1 倍速经营。阶段需 32／64／96 人等公共条件、主题目标及 1／2／3 个连续达标月；明确完成后才生成记录和奖励。主题分别关注住房余量、材料净流、平均污染上限、娱乐实际覆盖或通货净流，并调整未接取委托。

终局命名与地标选择要求 DT 为零且三个阶段已完成。保存终局记录不强制变成只读；`readonly` 是单独夹具。首次未结算、当前预估、已发生回执和历史完成记录各有独立含义。

## 说明边界

所有阈值、价格、产量、时间与阶段关系都是有限演示模型，为界面提供可操作的状态变化；它们不构成正式游戏的平衡结论。静态方案对比表示当前人口等条件下的完工差异，包含投入库存、月流、电力与环境变化，不模拟中间月份、未来移民或真实 RNG。

底图来自项目已有 Unity 展示画面，详细来源见 README；底图上的景物和网页的 19 格数据不是一对一的正式城市实体。没有接入实时引擎、正式存档、在线市场或离线补跑。

地图采用可交互 SVG 六角网格叠在历史底图之上，点击与数值以 SVG 地块为准。背景建筑不作为当前夹具建筑数量。原型没有逐地块库存台账，因此对应图层标为「材料月流」，色阶与标签均使用该地块的材料月净流，避免把流量误称库存。
