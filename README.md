# MET · 来生 0.5.0-beta.2

MET 是一款关于“把一个地方慢慢养成城市”的游戏：土地给你条件，居民给你需求，资源给你限制，委托给你机会，Bonus 给你特殊办法，而你之前做过的每个决定，都会改变下一步什么才值得做。

愿景与长期原则见[项目宪法](docs/PROJECT_CONSTITUTION.md)，本轮实施依据为 [Beta v3 设计包](docs/beta/design-v3/00_READ_FIRST.md)。设计目标、已经实现的规则、实际测试结果分别记录；设计文档不代表所有体验目标已经得到验证。

本版继续同一套城市模拟器、21 节点建筑专业化树与来生殖民城市视觉，加入有限 DT 的发展周期、年度与人口奖励、五个委任主题、重复 Bonus 与蓝图研究，以及 DT 耗尽后的城市尾声。当前只经营一个 Block，没有 District 或跨局能力继承。

Beta.2 重置界面与地图呈现：常驻状态收敛为四项，选中建筑按用途显示图形指标和一个主动作，完整管理进入档案；地图改为清晰地格、较小建筑和留有街巷空间的连接。档案先用容量、流向、来源贡献和阶段轨道引导阅读，升级与奖励横向比较，完整账本和规则按需展开。详见[实施与验收记录](docs/beta/UI_RESET_ACCEPTANCE.md)。

## 开始运行

需要 **Godot 4.7.2 Standard**，无需 .NET。打开仓库的 `project.godot`，等待首次资源导入后运行。默认桌面全屏，最低支持 **1920×1080**；整个 pre-1.0 不安排小窗口或不同分辨率适配验收。已有运行资源随源码提供；普通运行和核心测试不需要 Blender。

```bash
export GODOT=/absolute/path/to/Godot_v4.7.2-stable_linux.x86_64
"$GODOT" --headless --path . --editor --import --quit
"$GODOT" --path .
```

命令在仓库根目录执行；macOS、Windows 使用对应平台的 Godot 4.7.2 可执行文件。[构建与验证指南](docs/beta/BUILD_AND_TEST.md)提供独立测试目录、原生窗口、性能探针与源码打包命令。旧 0.4 安装包不代表本次 Beta 的导出或运行结果。

### 可选的 Living World3D 原型

Living World3D 是与 Beta 2D 路径并列的只读视觉纵轴。默认启动仍使用 GL Compatibility 和现有 2D 主场景；只有显式启动参数会打开固定 37 Hex Hero Valley。该场景包含四个建筑实例、一种河谷树木原型和连续河谷河道，由同一套固定白昼方向光照明。它不读取玩家存档、不改变模拟，也不代表完整建筑库或完整美术重制。

在支持 Vulkan 的桌面环境中，从仓库根目录运行：

```bash
"$GODOT" --path . --rendering-method forward_plus --rendering-driver vulkan -- --hero-valley
```

以旧 2D renderer 检视同一夹具：

```bash
"$GODOT" --path . -- --hero-2d
```

renderer 和 driver 覆写只作用于本次进程，`project.godot` 默认仍为 `gl_compatibility`。当前云环境的 Vulkan Forward+ 使用软件 Vulkan / lavapipe，不能据此宣称硬件 GPU 性能。完整模块、资产边界、复核步骤和验收状态见 [Living World3D 架构与迁移说明](docs/living_world/ARCHITECTURE.md) 与 [V1 验收记录](docs/living_world/ACCEPTANCE.md)。

### Unity 移植验证

新增独立 [Unity Hero Valley 工程](unity/METLivingWorld/README.md)，复用同一固定切片的真实几何、原建筑与树木实例，使用官方免费 URP/glTFast 管线。这一阶段迁移世界呈现、摄影与交互，尚未迁移城市玩法或完整 Beta UI；原 Godot 游戏仍可正常运行。Unity 实际运行和 macOS 构建需要有效编辑器授权；用户目前没有 Unity 账号，不能将源码或 Godot 导出验证称为 Unity 运行完成。架构和验收状态见 [Unity 移植记录](docs/unity_port/ACCEPTANCE.md)。

## 一局怎样推进

从农居、邻里中心和作坊建设城市，选择运营者，准备库存，再选择时间档位。升级改变建筑的用途和依赖关系，保留原建筑身份、运营者、库存和人群关系；方案槽随 Tier 逐个解锁。建设与升级仍共用施工能力，真实消耗材料。

| 时间档 | 本地时间倍率 | 作用 |
| --- | ---: | --- |
| 常速 | ×1 | 正常经营，不消耗 DT |
| 观察 | ×5184 | 较慢加速，便于观察缺口 |
| 推进 | ×25920 | 推进建设、生产与城市成长 |
| 燃烧 | ×77760 | 快速推进，需要提前准备供给 |

初始 **75 DT**。DT 为额外推进的本地时间付费，不随离线、普通目标或年度奖励恢复。稀有委任重铸另外消耗 7.5 DT。来生一天等于 36 地球小时，12 日一月、144 日一年；界面按来生日历显示，资源流量按来生月显示。

**暂停、后台和离线都冻结城市。** 离线只记录经过时长，不补算生产、贸易、移民、事件或奖励；本版没有 Reserve 恢复、兑换或消费玩法。重新进入游戏时回到暂停与常速，等待玩家继续。

移民按 **Local Time** 抵达，会随 DT 加速；外部货运和市场压力回归只按真实活跃在线时间推进，不会被 DT 倍率放大。货运站订单仍受运力、现金、库存、仓容和限价约束。准备库存和本地产能，因此会改变一次加速能走多远。

## 奖励、构筑与主题

每个来生年有一次普通奖励；入住人口首次达到 32／64／128／256 并稳定一来生月，各有一次奖励。两年大周期提供总结和事件，不额外重复发一份年度普通卡。

奖励统一保存来源、候选和领取状态，按队列处理；打开页面或读档不会重抽。同一 Bonus 可以重复出现、领取、储存和部署。每次安装消耗一份副本，卸下或替换不返还。同宿主第一份为 100%，以后每份追加 33⅓% 的数值强度，数值副作用同步变化；不同宿主各有自己的首份。槽位、资格、互斥与许可尺度仍须满足。布尔、关系、网络和加槽等结构效果不按分数复制；无新增收益的重复安装不会消耗副本。

工业基地、安居计划、商业引擎、港务枢纽、粮食腹地分别包含三个阶段，配有合计 15 个主题事件。年度与人口奖励独立于主题获得；主题阶段提供定向副本和研究。首批 12 张蓝图可从基础升级至改良 I、改良 II，影响本 Block 已安装、库存和以后取得的同名副本。研究无合法对象时转为主题副本；候选不足三张可以两选一或一选一，空池补偿 30 通货，不恢复 DT。

主题一经选择，只有取得稀有重铸权并支付 DT，才能更换尚未完成的主题。已获与待领奖励保留，未完成进度放弃，切回也不能重复领取旧里程碑。事件交付与市场出口分别记账，交出去的资源真实减少。

## DT 耗尽后的城市

DT **首次实际归零**时，所有城市获得一次命名权。只有在这个时点之前，或恰好在最后一段结算中完成主题的城市，才取得对应定型建筑资格。归零后继续常速经营再完成主题，不追补这次资格。

工会总部、管委会、商会、港务局、农业合作社总部提供各自明确的本地数值效果。地标可以稍后领取，满地图也不需要拆除玩家建筑；重复点击和同版本读档不会重复发放。

可以留在原城继续常速经营，也可以先保存只读城市记录，再独立重开。新局不继承资源、副本、蓝图、重铸权或地标。记录可从“河谷手册与存档 → 已结算城市记录”查看；不是可切换经营的多城存档系统。

## 查看与操作

本轮按[界面与地图重置合同](docs/beta/UI_RESET.md)分为四层：L0 仅常驻 DT、人口、粮食与时间控制；L1 放必要警报、当前主题与图层图例；L2 选中建筑后用图形指标和一个主动作呈现；完整来源、槽位、预算、市场、政策、升级树与历史进入主动打开的 L3 工作台。地块选址使用就地气泡，地图强调可辨地貌、较小建筑与街区连接。

- 滚轮缩放；中键或右键拖动地图。`1` 观察，`2` 建设，`Esc` 逐层返回。
- `P` 暂停或继续；空格选择推进档。需要先完成的奖励或事件会引导到决策页面。
- 时间 HUD 显示当前档位、DT 与来生日期；悬停时间控制或打开时间档案，可看剩余发展预算与现实时间估计。紧急缺口由独立警报定位。
- 建筑详情按住宅、生产、服务、物流显示不同信息。升级和安装前可查看变化与代价。
- 地图告警指向具体缺口；城市消息读取已结算状态并收入档案，不会自行改变模拟、库存或游戏随机数。

查看决策面板、比较方案和处理弹窗时，城市暂停。开发工具会标记存档，其补给不属于正常经营路线。

## 存档与城市记录

本版使用独立目录 **`MET-Laisheng-Beta`**，主存档为 **`met_beta_v6.json`**，最近备份为 `met_beta_v6.json.bak`。只读城市记录保存在同目录的 `city_records/`。游戏菜单提供打开存档目录、导出存档和导入当前版本备份。

| 平台 | 默认目录 |
| --- | --- |
| Linux | `~/.local/share/MET-Laisheng-Beta/`；设置 `XDG_DATA_HOME` 时跟随该目录 |
| macOS | `~/Library/Application Support/MET-Laisheng-Beta/` |
| Windows | `%APPDATA%\MET-Laisheng-Beta\` |

本次 Beta 不兼容 0.4 的旧格式存档，不迁移旧城或补发旧奖励。不会通过覆盖旧版目录来升级存档。同版本恢复会保留施工、订单、已保存的奖励与主题状态；城市归档失败时不会丢弃当前城市。

## 验证与范围

在仓库根目录运行核心与路线套件：

```bash
GODOT="$GODOT" MET_EVIDENCE_DIR=/tmp/met-beta-evidence bash tools/test_beta.sh
```

脚本会对失败返回非零，并逐项保存日志。本轮原生交互、地图和性能结果见 [Beta.2 界面重置验收](docs/beta/UI_RESET_ACCEPTANCE.md)；[Beta.1 验收报告](docs/beta/ACCEPTANCE.md)保留此前玩法结果，不能将旧界面截图当成重置后的验收。固定种子的自动路线不等于真人试玩，也不能证明所有种子或策略都已经平衡。macOS、Windows 的实机运行与真人体验需单独验证。

**整个 pre-1.0 阶段不开展移动端开发、适配、打包、实机验收或发布。** 唯一要求是设计时做好考虑、留好余量，包括架构、输入与界面、性能及资源预算。移动端缺少验证不构成交付阻塞；已有触摸代码、历史产物和报告不产生持续维护义务。1.0 及以后的范围另行决定。

人口阶层、组织总部成长、District、跨 Block 物流、跨局继承和完整 City 终局仍不在本次范围。定型建筑的“总部”名称不代表增加了这些远期系统。既有参数化微缩城镇视觉继续使用，不宣称完成了全面美术重制。
