# MET 0.4.0 · 专业化与委托

本版在 0.3.2 CityDesk / B 系谱上原位开发，采纳 `MET_0.4.0_开发架构方案_v1.md`，并将 0.3.3 的信息层级与地区命名纳入同一次交付。未发布 GitHub。旧版规则、服务分配、人口、场来源与资源结算仍使用原内核。

## 内容与成长

`content/040` 分开维护建筑、成长、运营商、许可、委托、市场、政策。开局和新建只有农居、邻里中心、作坊。21 个节点组成三棵完整树；每次升级保持项目、地块、运营者、库存、人群宿主和已安装方案的身份。T1、T2、T3 逐步解锁运营商的槽位轨道；普通改槽和付费更换运营商退出玩家路径。

Tier2/Tier3 节点的成本是本次升级支付的成本。升级期间，产出效率和服务能力暂为 65%，住房保持原状态直到竣工。升级后失去的多用途能力在预览中列出，住户通过原有重新安置逻辑进入可用住房。升级瞬间保留已有库存，多出新仓容的部分仍通过既有转仓与消耗逻辑处理。

城市基础施工能力为 4 CP/h；运行中的料场/货运站可增益施工。施工按优先级、稳定项目 ID 排序，建筑和升级共享这一队列。材料按实际 CP 进度扣除，缺材料或停工不会凭空推进；DT 只购买经过的时间。

## 许可与发展

招标只产生三个运营商候选并保留报价，重抽仍有原有成本。委托完成后产生一次保存下来的三选一，选中的方案获得一次部署许可。卸下和替换不退许可；同一 Block 的部署历史不会随卸下删除。安装资格在安装时检查，持续作用的条件仍由方案自己的 Rule 表达。

委托定义是数据，目标由真实结算指标和交付记录驱动。任务面板同时只管理一项主要委托；章节目标保留原有三个方向，完成后可继续经营。四项旧社区成果不再自动产生新的地区抽卡机会。

当前只开发单一 Block。城市目标完成后授予一次地区命名权，可以延后使用，也可以继续经营。命名只改变展示名称，不写 Trait/Label，不改变经济。District、移交、遗产携带和永久制度不进入当前版本，见 `OUTLOOK.md`。

## 贸易

Tier3 货运站提供实际贸易容量。粮食、材料、制成品通过订单逐周期成交，电力不跨区交易。订单受库存、仓容、通货、价格限制和共享贸易容量约束。价格压力按本地时间回归；外购推高压力、外销降低压力；买价始终大于卖价。负买价表示接收补贴，负卖价表示处置费用。订单与成交保留在当前 Block 的独立历史中。

## 存档

保存使用 schema5 和独立 `MET-RiverValley-040/river_valley_v5.json`。仅接收同一 pre-alpha 构建格式；不实现 schema3/schema4 导入、legacy 定义或历史奖励补发。用户明确要求整个 pre-alpha 阶段不考虑跨版本存档兼容。

当前版本的奖励三选一、许可证部署历史、施工与升级进度、订单和城市命名状态均正常持久化。同版本保存恢复必须保持状态与随机流一致。

## 验证边界

只以本次 `evidence040` 输出和 `TEST_REPORT_040.md` 为本版结果；历史目录不重命名为 0.4 证据。自动路线、核心直接构造用例、图形脚本与真人鼠标/触控操作分别记录。参数化街区填充是纯视觉绘制，不创建模拟实体、不消费游戏随机数，也不宣称纯图片模型资产管线。
