# MET 项目宪法

记录日期：2026-10-03。依据：项目所有者在本次对话中提供的愿景与设计总结，以及随后明确的 pre-1.0 移动端边界。

本文区分长期愿景、稳定设计原则、0.4 阶段产品需求和远期展望。设计需求不等于已实现功能；实际完成情况以当前源码及对应版本的验证证据为准。本文不将历史脑暴自动升级为开发任务，也不授权一次性实现全部系统。后续明确的项目决策可以修订本文。

**本轮 Beta 修订（2026-10-03）：** 用户已授权实施 [Beta v3 设计](beta/design-v3/00_READ_FIRST.md)。下文的 0.4 需求保留为历史基线；Beta 将 DT 改为有限高速发展预算，离线只记时间（不启用 Reserve），移民按本地时间，普通奖励来自年度与人口，主题委任提供额外奖励。同名方案允许重复库存/部署并按追加1/3数值强度合成，部分蓝图有两次升级。命名与条件性定型建筑改由 DT 首次实际归零触发。新旧冲突处以 v3 及用户后续明确决定为准；城市主角、真实因果、单 Block 和 pre-1.0 移动端边界继续有效。

## 一、愿景：把一个地方慢慢养成城市

> MET 是一款关于“把一个地方慢慢养成城市”的游戏：土地给你条件，居民给你需求，资源给你限制，委托给你机会，Bonus 给你特殊办法，而你之前做过的每个决定，都会改变下一步什么才值得做。

MET 要成为一款“城市本身会活”的持久化城市建设游戏。玩家读懂一个地方，在有限资源和有限主动权下塑造它；城市的既有结构不断改变后续选择的价值，并最终留下属于这一局的历史。

早期“非均值放置赛博盆栽”的愿景仍有意义：世界大多数时候自己生活，玩家偶尔进入高密度干预期，规划、建设、调整、构筑，然后把手拿开；下次回来，世界应该真的发生过变化。这是体验方向，不代表当前离线模拟已通过验证。

至少在 Wild 游戏线中，城市建设本身就是内容。MET 不再以“个人项目管理工具披城市皮”为定位，也不以精密报表为核心体验。玩家应该不断产生这些念头：

- “这里适合长成什么？”
- “我现在最想解决什么？”
- “这栋楼放这里居然特别值。”
- “这张 Bonus 上局没感觉，这局怎么突然这么香？”
- “再建一会，这里会变成什么？”

0.3.x 以后出现的“我开始憧憬：多建一会会怎么样了”，是值得保留的核心体验信号。接下来应当养完整这个循环，不轻易推翻重造。

## 二、稳定设计原则

### 1. 城市是主角

核心循环是：读懂土地和城市 → 发现具体问题或机会 → 在有限能力下决定怎么做、在哪里做 → 城市明显改变 → 改变自然制造新的问题、机会和欲望。

涌现、Rule、Field、Bonus 是实现体验的方法。地图上的城市是主角；Rogue / Bonus 决定这一局能用哪些特殊办法塑造城市。玩家首先看到地方、后果和选择，不应被大量 Bonus 说明书淹没。

### 2. 深度来自后续选择价值的改变

**深度 ≈ 路径依赖 × 系统交互 × 机会成本 × 可控的不确定性。**

评价新系统时，首先问：“我现在做这个决定，会不会改变以后什么值得选？”

真正的 Build 来自 A 让 B 变强，B 又让原本不值得选的 C 有用；位置、人口、污染和运营关系让同一张 Bonus 在不同局中价值不同。例如制造带来污染，回收因此有价值，热量管理再利用副作用。应让玩家自己发现并命名这种组合，而非硬编码“粗野制造 + 高级回收 = 工业套装奖励”。系统数量增加而路径依赖不增加，只会扩大负担。

### 3. 模拟：少写例外，多写语法

| 层 | 设计职责 |
| --- | --- |
| PopulationGroup | 不模拟个人；以群组记录数量、居住、就业、健康、教育、幸福、效率和需求。 |
| Building | 有位置、运营组织、Trait、效率、岗位、库存、输入、输出和服务容量。 |
| Tile | 坐标、先天 TileTrait、建筑，以及由 Field 计算出的空间状态。 |
| Field | 独立且带 Source 的空间实体；来源和传播规则不能被 Tile 永久抹掉。 |
| Resource | 简单库存量；建筑决定吞吐和转换。 |
| Organization / Operator | 建筑的运营关系，不是第四个 Slot；拥有 Trait / Rule 和领域偏好。 |
| Bonus | 一组 Rule，改变已有系统之间的关系，不只是增加属性。 |
| Policy | Block 级规则选择；固定制度槽，同槽互斥。 |
| Rule | 最小可执行句子；一条做一件事，可以读取多个对象。 |
| Simulation | 分阶段、确定性结算；同阶段不能靠执行顺序抢资源。 |

Bonus 可以改变数值、转换、Field、资格、关系、分配和解释方式；不要用大量专用组合判断伪装涌现。这些底层职责不应轻易推翻。

### 4. DT：主动干预预算

DT 的职责是 Agency Budget：允许玩家在一轮内强力干预城市，但不能无限操作。它不是血条，也不应退化为普通货币。

长期节奏是短时间高密度规划后离开，再回来发现变化和机会。玩家打开游戏时应尽量有有意义的操作，垃圾等待应发生在离开期间。数值可以调整，DT 的职责不要漂移。早期 DT、地形/邻接和稀缺操作预算带来的可玩性经验，应作为设计参考保留。

### 5. UX 与艺术

**最新呈现决定（2026-10-03）：** 按 [界面与地图重置合同](beta/UI_RESET.md) 实施 L0 环境、L1 状态、L2 情境、L3 档案四层；L0 仅 DT/人口/粮食/时间，L2 至多三个图形指标与一个主动作，详细管理主动进入 L3。地图改为清楚的六角地貌与资源表达，建筑缩小并留出街巷和跨格生长空间。整个 pre-1.0 默认桌面全屏、最低 1920×1080；不安排不同窗口尺寸测试。下表保留此前信息收敛原则的来源，不再用旧页面编号覆盖新四层定义。

隐藏数字不等于简洁，同时展示所有数字也不等于透明。地图常驻，信息逐层展开：

| 层级 | 职责 |
| --- | --- |
| HUD | 只报当前状态。 |
| 一级主题 | 解释财政、人口或某项资源的整体情况，一页一个主题。 |
| 二级 | 管理与选择，让玩家决定处理收入、就业、需求或供给中的哪部分。 |
| 三级 | 完整来源、长表、Rule 和历史。 |

艺术方向是“人文工业微缩城镇 + 市政分析图”：平时是一座值得看的城市，切图层时成为清楚的规划图。

城市视觉应随发展变化：主建筑按格建设，相邻发展地区间长出小房屋、店铺、仓棚、街树和道路肌理；街区逐渐变密、变高、变现代。填充物初期属于视觉层，不为每栋小屋新增模拟 Entity。表现读取真实模拟状态，不反向改变模拟；停工时不能仍用冒烟等表现伪造生产。

**独立视觉轴（2026-10-03）：** Living World3D 是与 2D Beta 并列的可选只读展示路径，使用 detached 的已结算状态、独立资产 registry 和共享固定白昼光。其 V1 目标是固定 37 Hex Hero Valley、四栋建筑与一种树木原型；它不取代 2D 世界、不改变游戏或存档逻辑，也不意味着其余建筑已经覆盖。默认仍以 GL Compatibility 打开现有 2D 主场景；只有显式运行 `"$GODOT" --path . --rendering-method forward_plus --rendering-driver vulkan -- --hero-valley` 才启动 3D 切片。具体模块合同、许可口径和迁移阶段见 [Living World3D 架构说明](living_world/ARCHITECTURE.md)。V1 运行与画面结论须等[验收记录](living_world/ACCEPTANCE.md)提供实际证据后再写，不以设计目标代替完成证明。

## 三、0.4 阶段产品需求基线

本节记录设计目标，不是完成清单。0.4 只做一个 Block；整个 pre-alpha 不提供跨版本存档兼容。当前成长、Commission、Bonus 与 Market 稳定之前，不同时展开全部远期路线。

四个核心方向：城市成长提供继续建设的理由；Bonus Economy 让能力由游戏行为挣来；Commission 提供阶段目标和三选一奖励；Market / Trade 给过剩与短缺真实的外部接口。

### 1. 从三个起点走向专业化

| 起点 | 成长方向 |
| --- | --- |
| 农居 | 住宅 / 农业 → 高级住宅 / 现代农业。 |
| 邻里中心 | 公共中心 / 诊所 / 初级学校 → 商圈 / 公园 / 医院 / 中学校。 |
| 作坊 | 动力站 / 开采站 / 料场 → 发电厂 / 材料工厂 / 制造工厂 / 货运站。 |

这是成长方向概述，具体节点与分支映射以版本设计为准。Tier1 多用途但低效；越往上越专业、吞吐越高、对其他系统依赖越强。升级回答“这个地方变成什么”，而非“LV2 加多少百分比”。从直接建造十种建筑转为三个 Tier1 起点和专业化升级树，并相应调整招标、Bonus、委托和施工。

### 2. Operator 决定运营与成长轨道

Operator 不再提供 Bonus，而是回答“谁来运营，这栋楼天生适合怎样成长”。它决定领域倾向、Slot Track、自身 Organization Rule 和投标出现权重。

Slot 随升级逐个出现，例如 Tier1 Production、Tier2 Logistics、Tier3 Operations，不是一出生就有三个槽。已经长出的槽普通情况下不能随意重铸，使建筑留下历史。Operator 跨界采用低概率而非硬禁止，但候选应与领域有合理关联。招标方向为 Operator-only Tender。

### 3. Bonus 是挣来的部署许可

常规获取链为：完成 Commission → 三选一 → Bonus License ×1，取代花钱无限征集 Bonus。

普通 Bonus 默认在一个 Block 只部署一次；安装消耗许可，拆除或替换不返还。许可与已安装的 bonus_instance 分开。稀有奖励才可能允许复制、标准化、扩大范围或多次部署。玩家需要认真决定“这张高级回收给谁”。

### 4. Commission 是真实局面的阶段挑战

城市状态生成候选，玩家选择少量主要委托，解决真实问题后获得三选一能力，不做“建三栋楼 / 在线五分钟”的任务墙。

可用方向包括：不断电完成工业交付；改善某片住区医疗覆盖并维持一段时间；在不利价格下完成出口。它们是设计例子，不是已实现任务声明。

奖励池结合任务领域、城市状态和未来 Slot，目标是两张现在有意义、一张可能诱导下一阶段发展。奖励应扩展 Build 的可能性，而非只发钱。

### 5. Construction Capacity 让大型项目产生取舍

Block 每小时有有限施工能力 CP，建设与升级共享队列；小农居、医院和大型制造厂的施工需求应有实质差异。多个工程竞争能力，Material 真实消耗，DT 推进时间但不绕过施工能力。由此形成“先建医院，还是先投资施工能力”的机会成本。

### 6. Market 是小而真实的外部世界

货运站是外部市场接口，交易 Food、Material、Goods，受 Trade Capacity 限制，不能瞬移资源。

价格模型考虑基准价、市场压力、市场深度、买卖差、手续费和回归：大量买入涨价、大量卖出跌价，随后向基准回归。允许负价格，但必须保持 Buy Price > Sell Price，防止直接价差套利，并遵守资源与资金守恒。它为城市的过剩和短缺建立外部出口，不在第一版扩展成完整宏观经济模拟。

### 7. Block 目标与命名权

从登陆聚落成长为能够独立运作的社区，城市自身持续提出问题。达成主要目标意味着获得结束或结算资格，不强制结束；玩家可以继续体验 Build。

完成主要城市目标后获得一次地区命名权。这是让地方成为“我的地方”的非数值奖励，不改变 Trait、Rule 或经济。

## 四、远期展望：不能自动转为当前任务

0.4 不实现 District。跨 Block 继承、District Doctrine、下一 Block 启动 Bonus、跨 Block 物流和区域总部仅作展望。未来可能让 Block 承载一次完整构筑，更长层级保留少量历史与制度。City 的远期终局愿景是“托卡马克之冠”，不是把 Block 通关当成全局终局。

其他未来方向：

- 人口细化：PopulationGroup 发展为类似 City Life 的文化 / 阶层体系，不同群体具有住房、工作、消费和服务偏好。
- 组织深化：Operator 的友好度、发展程度、区域存在、总部和组织历史。
- 污染进一步物理化：Pollution / Noise 作为 Field，Garbage 作为 Resource。
- 城市肌理深化：小建筑与街巷随 Tier、活跃度及关系增强而更密、更现代；遵守视觉层与模拟层边界。

这些方向建立在当前核心稳定之后，不构成这一轮的交付要求。

## 五、阶段边界：pre-1.0 移动端

整个 pre-1.0 阶段不开展移动端开发、适配、打包、实机验收或发布。移动端唯一要做的是：**做好考虑，留好余量。** 在架构、输入与界面、性能及资源预算上合理预留，不把预留扩展为专项工作。移动端验证缺失不阻塞交付，历史代码和产物不产生持续维护承诺；1.0 及以后的范围另行决定。

## 六、接手项目先读的十二条

1. 城市是主角，卡牌不是主角。
2. 玩家应该不断产生“下一件我想做的事”。
3. 每个重要选择都应该改变后续选择的价值。
4. 随机性决定“怎么长”，不能剥夺基本建设能力。
5. 不要隐藏因果；复杂性要藏在系统里，不要糊在脸上。
6. 地图必须参与决策：为什么是这里，而不是另一格。
7. 资源必须制造机会成本，否则只是库存数字。
8. 升级是专业化与身份变化，不是简单 +20%。
9. 奖励应该增加玩法可能性，而不仅是增加数值。
10. 有事做的时候必须好玩；没事做的时候应该允许玩家安心离开。
11. 视觉变化必须反映模拟变化，不能城市停工了烟还在冒。
12. 每增加一个系统，都问：它是在增加深度，还是只在增加广度？
