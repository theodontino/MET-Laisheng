# 02｜为什么不是简单换皮：当前实现的具体缺口

以下是实际源码事实；修法属于本方案决策。更多定位见 `specs/01_BASELINE_AUDIT.md`。

| 当前事实 | 对体验的影响 | 0.3.0 修法 |
|---|---|---|
| `map_view.gd:33–35` 地图半径与控件宽高绑在一起，镜头以整图为中心 | 城市小、空地多；侧栏出现时地图尺度会跟布局牵连 | 固定世界坐标＋独立镜头；默认框住已建区及邻近建设空间 |
| `map_view.gd:92–99` 服务层取四类可达性最大值，再按住户“最好两种服务”着色 | 一片绿色不知道代表医疗还是休闲，也不知道是否抢得到容量 | 四个明确子图层；分别展示范围、实际分配和容量短缺 |
| `map_view.gd:87–89` 环境／余热按固定除数与地形色混合 | 地形底色影响读数；场贡献与实际利用容易混淆 | 独立分析底图、固定图例、源贡献／利用量分开 |
| `map_view.gd:48–64` 有鼠标与 Pan/Magnify 手势，没有完整单指点拖状态机 | 不能据此宣称完整手机操作 | 加 ScreenTouch／ScreenDrag 适配，按松手与移动阈值区分点击 |
| `app.gd:114–136` 十建筑常驻等宽按钮，1050×625 固定模态框 | 主次雷同；手机尺寸根本放不下 | 分类工具盘＋响应式详情；投标变地图旁的工作面板 |
| `app.gd:252–259` 投标模态窗是否可见，会影响本地自然时间推进 | 换成非模态投标后可能不小心改变游戏时间规则 | 决策暂停原因独立保存，不能再由某个遮罩是否显示决定 |
| `planning.gd:19–73` 已能用真实内核预测，但主要返回总量与少量对象变化 | UI 没有足够的按住宅、按来源差分来画后果 | 补只读展示结果，不另写一套经济公式 |
| `map_view.gd:30–32,124–129` 每帧整图重画，还遍历所有建筑对画相邻路 | 素材变复杂后成本会上升 | 静态层缓存、六邻居接路、动态效果单独更新 |

关键结论：**现有模拟信息能支撑升级；但部分图层查询和交互状态必须随美术一起改。** 这不是“资产替换即可”。

# 03｜美术方向：定这一套，不再同时试五种

## 3.1 风格名与边界

**风格：人文工业微缩城镇。**  
温暖、明亮、清楚、有秩序，但不幼儿化；从农场、红砖工场、社区诊所，可以自然生长到现代科研与能源设施。未来感来自干净的公共空间、设备和材料，而不是满屏霓虹。

**表现：固定高俯视的 2.5D 插画精灵。** 城市规则依然用当前正六边形与轴坐标；不引入三维摄像机，不允许自由旋转，不把已经建好的世界变成另一张斜棋盘。建筑可以画出屋顶和两侧体积，地面仍服从当前格子。

这是风格化俯视，不追求严格等距工程投影。生成提示中的“约 60° 高俯视”是制作引导，**最终以与游戏地面叠合是否一致为准**。不接受同一批素材里混入低机位透视建筑。

## 3.2 视觉约束

- 光从屏幕左上方来；主体允许少量自身阴影，接地阴影单独由程序画。
- 地面低对比、建筑中对比、选择／警告高对比。温暖不等于全部发灰。
- 无厚描边贴纸感，无每格悬浮厚底座，无写实摄影拼贴，无夸张玩具塑料高光。
- 不生成文字、品牌、运营商徽章、动态烟、电力条或状态图标进建筑主图。
- 河流连成河，山地连成地势；常态不画所有内部格线，只保留轻的可建区外边界。
- 建筑脚下的院子、树、堆场是视觉配件，不变成新操作或额外容量。
- 建筑改造不修改先天 Trait；外观可以表达正在运行的用途或 Bonus，历史身份仍来自原数据。

## 3.3 十类建筑的识别合同

| 现有 ID | 主轮廓 | 配景 | 不得混淆 |
|---|---|---|---|
| hamlet | 两到三栋低层联排住宅，暖屋顶 | 小院、路灯、树 | 不用工业锯齿屋顶 |
| farm | 农舍＋明确成行田块 | 水槽、矮篱笆 | 田块由可复用地面组件补，不画一个固定六边形底板 |
| timber | 低矮材料棚＋露天料堆 | 木材／石料混合堆场 | 仍是通用材料设施，不额外暗示已拆分石木资源 |
| power | 低矮动力房＋可拆分风轮／能源设备 | 设备底座 | 旋转部分单独处理，停机不得永远转动 |
| works | 红砖锯齿车间＋一根短烟囱 | 装卸庭院 | 不把烟画死；不要过高遮住后排地块 |
| market | 开放式棚顶／连续檐篷 | 摊位和小广场 | 与仓库封闭大门区分 |
| school | U／L 形浅色教学楼＋院落 | 操场／书院庭院 | 与诊所通过结构区分，不靠文字 |
| clinic | 紧凑平顶楼＋清楚的入口雨棚 | 青色心形诊疗标识 | 不使用真实组织标识，不靠红十字换皮 |
| park | 环形步道＋中央树冠／小亭 | 座椅、草地 | 不画成额外一栋学校 |
| warehouse | 连续卸货门＋大跨度仓棚 | 箱堆、门前硬地 | 与市场的开敞摊位区分 |

在正常建设缩放下，不读名称应能区分十类；远景改用功能小标识辅助，不强迫微小图片同时承担全部信息。

# 04｜素材怎么做：AI 做可复用对象，程序做精确关系

## 4.1 本轮资产规模

**30 个 AI 视觉资产：10 个主体＋12 个共用装饰＋8 个规则配件。**  
另有程序／矢量制作的 32 个功能图标、8 个运营商徽记、6 个轻量反馈音。共 76 条制作任务，全部列在 `config/asset_manifest.json`。

十种主体必须全部替换完成再交付，不交一半旧几何、一半新插画。三座样本先校准风格只是同一工程的制作工序，不是新玩法原型。

40 张 Bonus 不需要 40 张专属插画。方案图鉴先用“主体缩略图＋槽位图标＋两条短效果”。8 类关键配件表达仓储、余热、回收、开放活动、再开发、都市农业、复合职能、无人机设施，其余 Bonus 用实际关系／图标说明，不伪造外观能力。

## 4.2 工序

1. 用住宅、工业厂、诊所三份同规格图校准母版；放入**现有城市**并按真实小尺寸检查。
2. 后续素材都引用母版，不靠相同提示词从零生成。GPT 的跨次一致性与精确构图仍需检查。[R1]
3. 每次一栋或一个独立组件；保留原图、提示词、参考图标识、生成工具版本和选用记录。
4. 透明通道必须检查是真透明，不是棋盘背景或白色描边。失败时用可靠分割或重新编辑；不能一键删白把浅色墙也删掉。
5. 裁切、统一比例、设锚点、标入口／烟口／配件挂点、导出运行纹理。
6. 在普通图、分析图、浅深背景与缩小状态中检查；通过后才能加入图集。
7. 素材无实时联网依赖。游戏运行时不请求图像模型，不把用户的联网与订阅当成美术加载前提。

具体母提示、十栋建筑提示和退回标准见 `specs/02_ART_PRODUCTION.md`。

## 4.3 尺寸和图集默认值

| 项目 | 制作母版 | 游戏运行尺寸 | 说明 |
|---|---|---|---|
| 建筑主体 | 1024×1024 | 512×512 | PNG／WebP 真 alpha；归一化地面锚点默认 (0.5,0.75)，整理后记录实际值 |
| 装饰与配件 | 1024 母版或同尺度编辑 | 256×256 或更小 | 全部可复用，禁止一物一张4K |
| 图标／徽记 | SVG 24／32 基准 | 按 DPI 清楚渲染 | 原生文字另放；不依靠系统 emoji |
| 世界图集 | — | 2048×2048 页面 | 目标不超过2页；增加第3页须重新核查内存 |

图集边缘留 8px 扩边／隔离，并检查 mipmap 低层不会采到邻图。缩放世界纹理使用线性采样与合适 mipmap；UI 图标不跟着世界缩到发糊。

制作母版不打进玩家包。透明压缩、图集、纹理内存须按实际导入结果核对；磁盘压缩体积不是显存占用。[R5]

## 4.4 可持续维护与版权来源

生成的建筑不复刻其他游戏的专属建筑、图标或品牌。参考的是信息组织与清晰程度，不提取商业游戏资产。所有外来素材留来源和可分发许可记录。

字体在工程内统一选用带有明确分发许可的中文无衬线字库，建议 Noto Sans SC Regular／SemiBold；拿到许可后再纳入游戏资源清单。**本方案包不附字体文件**，也不把系统 PingFang 直接拷入跨平台发行包。没有核验许可前，字体任务不得标为可发布。

# 05｜镜头、地形和城市整体

## 5.1 先解决“地图很大，城很小”

世界坐标与面板尺寸解耦。沿用轴坐标换算，逻辑半径统一为 64 世界单位；画面上的大小只由镜头变换决定。旧 Tile ID、邻接、建筑位置不变。

初入旧城／新城时镜头框住“已建建筑＋周围两圈可建设空间”；已有建筑范围过大时优先框最近关注区。提供两个按钮：**回到社区**与**看全地区**，不再只有强制整图居中的“归位”。

正常规划目标：每格横向约 88–132 个逻辑单位，紧凑触摸界面约 64–100。数值是本方案的设计目标，不是引擎限制。缩得更远时，点一下只定位并放大，不立即建设。

鼠标滚轮以指针为锚点缩放；触控板／双指以手势中心缩放。打开侧面板不改变世界比例；必要时平移，使当前地块进入未被遮挡的可用地图矩形。移动或捏合期间停止自动镜头追随。

## 5.2 连续地形，不改变真实可建边界

- 水格共享边不画内部缝；只在水／陆边画岸线，采用边缘掩码与拼接规则。
- 森林与高地按相邻类别连接装饰，不给每格一个封闭小山盆。
- 肥沃、水岸等玩法 Trait 用选址／地形分析时的符号显示；表面草纹不等同于额外数值。
- 道路仍按现有规则自动表现连接。改用六邻居遍历，而非每帧所有建筑两两检查。
- 建筑外场与邻接线不能穿过一堵视觉上“不可通行”的假大山；不增加真实路径规则的前提下，避免绘制这种误导性障碍。
- 世界外围可延展低细节风景，但有明确不可建外边界，不能让装饰地看起来也是可操作格。

## 5.3 遮挡与细节层级

建筑按屏幕地面锚点 y 和稳定 ID 排序。大树、烟囱不得遮住邻格中心。规划时遮挡目标的前景主体可降到 35% 不透明，目标格与确认标记画在最上层。

远景看区域与警告；正常距离看主体和服务结果；近景才出现庭院配件、库存箱堆等。默认不常驻全部名称、人口数、收益倍率。悬停／选中／需要处理时才出现标签，标签不随地图无下限缩小。

# 06｜统一界面：玩家工作台，不是对象清单

## 6.1 视觉规范

完整 token 见 `config/ui_tokens.json`。界面基色为近白纸面、深墨文字、深青主操作，暖赭用于选择和建设；城市不整片染成界面主题色。

默认文本 16 逻辑单位，紧凑触摸 17；关键值 20；标题 22／26；辅助说明 13–14（手机重要正文不得用辅助字号）。正文、次要文字均做至少 4.5:1 对比检查；非文字重要符号和禁用状态仍保留形状及足够对比。[R6][R7]

间距阶梯 4／8／12／16／24／32；圆角统一 6／10，不是所有元素都画成等权重圆角大卡片。强调只给选中的主动作，普通按钮轻，危险动作单独确认。

## 6.2 桌面／大平板框架

- 顶部约64高：一行当前目标＋预算/现金流、DT、居民/住房；政策与账本为次级入口。
- 最多两条真实城市消息，作为地图角落可收起提示，不横铺两条空白巨栏。
- 地图铺到可用背景，不再套三重面板边框。
- 底部工具仅四类：居住、生产、商业、公共；展开一类才出现对应建筑。
- 资源条常显库存＋简短供需／浪费状态，点开看完整产／用／弃与来源。电力按供给／需求显示，不冒充库存。
- 选中建筑时右侧详情 320–360宽；关闭后地图仍保持原焦点和尺度。
- 分析工具是一个固定图层入口＋当前图层标题／图例；不永久铺十几枚等权按钮。

## 6.3 横屏手机框架

按安全区内逻辑尺寸布局。最低布局目标为 **640×320**；实际支持的机型在真机检查后公布。小于此可用面积或异常字体倍率，使用可滚动紧凑面板，不裁掉主按钮。

顶部48高只放目标简态、预算、DT和菜单；居民与住房进入可展开状态组。底部56高为建设、图层、选中对象与推进。资源详情从状态组一触打开，严重短缺始终有显眼状态，不因紧凑化隐藏。

规划／投标使用右侧280–304宽工作面板；余下至少约一半地图宽度保持可操作。具体长规则在独立详情页看，返回不丢当前地块和报价。三份投标用三行56高摘要保持同时可见，点某行切换地图预览；不复制三列长文。

**低高度布局必须算得下。** 规划／投标右面板占安全区的完整高度，不再套在顶部48和底部56之间；这些栏只覆盖左侧地图区域。在320–379高时，右面板使用：上下内边距16＋标题32＋共同成本32＋三行摘要168＋行间距8＋固定确认48＝304。每行两行短文，长名称省略但可展开，关键成本不截断；本档不在摘要列表下面硬塞完整详情，点“详情”在同一面板切页，返回恢复三选比较。高度≥380时再显示当前方案的简短收益／代价细节。字号放大后允许摘要区滚动，确认栏始终固定；不谎称所有字号下三份长文都能同时放下。

电脑也可切换紧凑布局。判定基于安全区逻辑宽高、输入模式和用户字号，不以物理像素宽度猜设备。

## 6.4 控件不会因为屏幕小而缩成蚂蚁

统一主要触控目标至少48×48逻辑单位、相邻目标间至少8；落地时核对 iOS pt／Android dp 的实际尺寸，不把44物理像素冒充44pt。Apple 对高频游戏控件建议44×44pt，Android建议48×48dp。[R2][R3]

保持 `canvas_items`，由布局适配器按屏幕密度、安全区和字号生成逻辑空间，再使用响应式容器重排；**不得将1440×900整套等比压进手机**。大屏设计尺寸只是参考稿，不是手机的固定虚拟画布。保持UI清晰、世界独立缩放。[R4]

# 08｜地图图层的完整语义

**一个主着色层＋一个选中对象关系层。** 不同时把污染、就业、服务和运营商都涂在地上。下列不是新增模拟系统，只是读取既有结果。

## 8.1 图层规范表

| 图层 | 直接数据 | 地图表达 | 选择后看到什么 | 绝不做 |
|---|---|---|---|---|
| 地形与选址 | Tile Trait、已有规则预估 | 图标/边界标有意义的地形；悬停当前格显示收益 | 该位置的一次真实预测 | 把额定倍率叫“推荐分” |
| 环境 | 结算后的污染Field来源；人群实际环境暴露 | 固定分档色带；居民受损单独标记 | 分来源贡献与规则解释 | 每屏自动拉满色阶、把净化量当可回收额度 |
| 余热 | Field贡献、实际热量额度／使用记录 | 热源轮廓＋实际接收标记；范围可展开 | 产生、分配、使用、剩余或损耗 | 覆盖到就算每栋都得到全量热 |
| 医疗 | medical场、服务分配、医疗有效容量 | 可达轮廓；住宅满足率；容量不足用斜线 | 提供方、实际人数、未覆盖原因 | 用四种服务最大值代替医疗 |
| 教育 | education同类记录 | 同一语法，青蓝书形图标 | 学校和教育来源、实际覆盖 | 把知识余额冒充服务名额 |
| 购物 | commercial同类记录 | 同一语法，市场图标 | 顾客、有效容量、供给短板 | 把休闲同时算进购物 |
| 休闲 | entertainment同类记录 | 同一语法，树／活动图标 | 公园等实际服务及竞争 | 够得到就当作已服务 |
| 就业 | employment_links、人群剩余劳力、建筑岗位 | 可切“居民找工作／建筑缺人”；选中后连线 | 人数、来源、有效劳动、主要约束 | 用运行率冒充人数到岗率 |
| 资源／电力 | activity_ledger、audit、分配收据和库存 | 四子类；来源/需求/库存符号与短缺热点 | 谁供给、谁消耗、谁被拒绝及原因 | 发明价格、货车路线或电网断线 |
| 运营商 | operator_org、方案提供方／重签关系 | 功能原色保留；外圈徽记区分组织 | 同组织项目与已有生效协同 | 把建筑功能全涂成组织颜色 |
| 改变预览 | 同一基线的before／after差分 | 得益为实线正号，受损为虚线负号 | 谁变化、变化多少、预测条件 | 把图层变成修改后真实状态 |

## 8.2 服务层必须区分三件事

1. **能到达**：从相关服务提供者的场值判断资格；同来源经中转出现多条样本时按当前规则去重，不复制容量。
2. **被服务**：来自实际有限容量分配；住宅按人群人数加权，不能简单平均不同大小人群。
3. **为什么没被服务**：分为够不到、提供者未运行、提供者容量不足、当前需求未激活／数据未结算等。不得把所有失败写成“距离太远”。

没有人口的空格不显示“0%服务差评”，显示可达范围或不适用。无家可归等地图外人群在图例旁列出，不偷偷从全城分母里删掉。

服务率配色区间默认0、(0,0.5)、[0.5,0.75)、[0.75,1]；**75%是现有宜居成果的服务目标，不是所有服务都只有四个物理等级**。具体目标不同则取对应目标值；0和无数据用不同纹理。

## 8.3 环境与热的量纲要诚实

当前没有真实空气浓度／温度单位。界面使用“环境负担指数”“本周期可用热量”，不能写µg/m³或°C装作拟真。

原代码里环境1、余热4等用于着色的常数，只是显示范围；新配置中明确标为**显示刻度，不等于健康阈值**。固定刻度跨视口保持一致，超范围用末端加箭头与实值，不重新映射最大值造成“同样颜色不一样的污染”。

受影响方向必须读实际规则：负场、特殊污染聚合、隔离防护均可能改变结果。显示原始来源与当地实际解释的区别，不能把视觉聚合后的一个sum强行当所有人的真实效果。

## 8.4 线、标签和图例

默认每个选中对象优先画6条最相关连接，旁注“另有N条”；提供查看全部。关系线粗细表示量，端点箭头表示方向；源与目标可点定位。隐藏只是视觉限量，不改变总量或计数。

分析图层数据缺失为灰斜纹／“未结算”，不是数值0。所有图层标实际周期或“下一周期预计”。颜色、虚实、符号共同编码，不仅靠红绿。[R6]

# 09｜建设、投标、改造：保持地图在场

## 9.1 六个明确状态

`观察 → 选择基础建筑 → 放影子／换地 → 比较投标 → 确认建设 → 回到城市`

每一步可回上一步，不额外扣钱、不丢同组报价。候选选择只改变预览，不落地建设；主按钮写“采用并建设 · X通货”，不是模糊“确定”。

## 9.2 选址卡首屏只回答四个问题

- **能解决什么**：预计产出／新增实际服务人数／住房容量。
- **付出什么**：一次造价、材料、工期、运营维护和主要投入。
- **挤占谁／影响谁**：明显下降的建筑、环境负担增加的住宅。
- **主要不确定性**：缺工、缺料、服务已覆盖、尚无可回收源。

产出显示预计与额定的区别，空房不叫新增人口，可达性不叫服务效率。不是每栋楼同样展示20个数；关键成本始终保留。

## 9.3 投标：比较工具，不是阅读遮罩

桌面底部工作台占不超过约300逻辑高，共用底盘一行，三份方案摘要并排；右侧详情区可收起。手机右侧三行摘要＋当前详情＋固定确认栏。地图可平移、点地、看差分，不在场景外展示另一张假地图。

每份摘要包括：方案名、运营者徽记、三个槽形、两项主要改变、一项主要代价。提供方与运营方相同通常不重复占两行；确有同源奖励／重签差异时出现明确小提示。

所有方案按相同基线、相同格子、相同周期比。**地图上的“本次改变”必须比较两条同一时刻的预测：不采取行动的下一周期，与假定方案完成后的下一周期。** 不能直接拿现在与下周期相减，把自然变化算成新建筑的功劳。不行动的基线预测可在本次比较中共用缓存；当前实际值可另列，但标签必须不同。

切候选时可分别显示粮食、服务、能源等真实变化，不给一个混合经济审美的“综合93分”。每项预测说明“假定建成，按当前城市下一周期”。

**时间语义必须保留。** 0.2.1 的投标模态框会暂停本地自然推进。换成地图旁的面板后，用独立的“决策中”状态维持同样暂停语义，显示“比较中 · 本地时间暂停”。这不等于暂停所有全局时钟，不改DT既有恢复规则。取消／确认后按原逻辑恢复。不得为了图层能操作而悄悄让居民在玩家读报价时饿上一个新周期。

## 9.4 预测过期与错误

界面记录预测基线版本、周期和候选。建筑/政策/城市变化后旧结果标“更新中”，先保留淡化值但禁用依赖过期预算的确认；完成后替换。预测失败显示原因，不显示0产出。提交前重查预算、格子和槽位；若重要代价变了，展示新旧差额并再确认。

后续改装也走同一工作流：选槽→看候选→地图上看改变→明确确认替换。既有方案停用、失去槽位依赖、重签成本必须在同一页指出。没有必要给用户再读一整篇Rule配置。

# 10｜经营与目标：美术版不丢掉“为什么行动”

继续使用0.2.1的“稳定生活＋任选城市成果”，不新增评分货币。顶部目标压缩为当前阶段与一项最相关进度；点开再看全部阈值、服务与交付内容。[B1]

消息第一句说明问题、对象、量或时间；提供“定位”“看解法”。不把消息点击直接绑定成“只能再建一栋”：缺医疗时先看现有容量／人手，再提供造诊所、改造等已有解法。自动提示只指出阻碍，不替玩家选最优流派。

建成反馈分两次：

- **完成瞬间**：建筑落地、施工设施撤走，显示预计将提供什么；这不是已经发生的真实服务。
- **首次运营后**：从活动账本显示实际产量或新增服务、目标推进；未达预计时说明首要瓶颈。

之后不每Tick弹奖励。重大成果一次庆祝，可跳过、不截断正常操作；欣赏模式只隐藏界面，不增加免费时间暂停，也不改变模拟规则。

# 11｜移动输入与可用性边界

- 单指／鼠标左键：松手时判定点击。超过8逻辑单位移动，进入拖地图；双指加入后取消待点击。
- 双指缩放／触控板捏合：以手势中心为锚，结束不残留一次点击。UI上的拖动属于UI，不能透传给地图。
- 桌面中键／右键平移保留；空格推进下一变化，输入框有焦点或决策中不触发；Esc逐层返回，不直接丢整份方案。
- 长按只作为查看捷径，不承载唯一信息。所有hover信息都有点击后的等价入口。
- 缩远到无法可靠点格时，首次点选定位放大，不强行把小格的触控命中范围扩张到互相覆盖。
- 字号可100%／125%／150%，关键内容放不下时换紧凑布局或滚动，不截成本。减少动态、提高对比、关闭闪动和音效可设置。
- 横屏为0.3.0手机完整建设方向；竖屏不另做完整城市编辑。平台层旋转不丢选中地、报价和草稿；桌面窗口窄时可进入紧凑面板。
- 系统中断／切后台先保存，恢复按既有时间策略；不因为设计改版新加离线饥荒或双倍DT恢复。

以上是同一应用跨屏适配。模拟触摸和窗口截图不能替代真机触摸、系统安全区、热量／续航检查。[R2][R3][R4]

# 12｜Godot工程落点：只改需要改的层

## 12.1 建议新增模块

```text
ui/
  app.gd                    # 保留入口，逐步只负责连接模块
  widgets.gd                # 统一Theme，去除散落字号/颜色
  presentation.gd           # 人话与状态摘要，继续复用
  shell/                    # HUD、目标消息、响应式工作面板
  map/                      # 地形、建筑精灵、分析覆盖、关系、标注
  input/                    # 鼠标/触摸 -> 同一组界面动作
  view_models/              # 只读地图数据、规划差分，不结算经济
content/presentation030/
  ui_tokens.json
  art_catalog.json
  layer_definitions.json
  bonus_visual_bindings.json
assets/world030/
assets/ui030/
core/planning.gd            # 扩展只读返回值，不改变真实世界
```

名称为本方案建议，不冒充现有文件。每个模块服务当前游戏，不构建通用商城或另一个前端。

## 12.2 场景与绘制顺序

`静态地表 → 可视地形细节 → 地面道路／院落 → 分析填色 → 地面阴影 → 按锚点排序的主体与配件 → 范围边界／关系 → 影子建筑／选择轮廓 → 屏幕标注 → UI`

分析状态对无关主体着色变淡，不删除建筑；可达边界和选中轮廓处于可辨认的上层。常态不渲染不需要的全屏模糊。静态地表、岸线、道路在结构变化时重建；运行烟、风轮、进度、提示为独立动态层。

移动端采用简单精灵、线、网格着色即可实现的效果，暂不依赖重后处理。保留 Compatibility 作为起点；最终设备表现要实测，不能只因“2D”就声称流畅。[R8]

## 12.3 数据接口必须补全，但不复制模拟

只读地图模型至少带：`snapshot_id / simulation_tick / actual_or_forecast / source_phase / tiles / buildings / groups / links`。所有前后差分来自同一次基线，严禁把当前库存、下一周期服务、上一周期环境无标记混成一幅“现在”。

`planning.gd` 扩展结果：各住宅服务前后值、每种服务的新增/失去人数、建筑运行前后差、环境贡献差、资源分配变化、可解释主要来源、预测时间。比较结束只留所需展示数据；不把全部clone放进每格长期缓存。

缓存键包含城市revision／tick、基础建筑、格子、报价实例或槽位上下文。不要依赖JSON字典偶然排序来定义唯一key。缓存用有上限的LRU，建议16份完整候选差分；过期响应不得覆盖新选择。候选多时排队，优先当前选中，不能为所有地块每帧重跑模拟。

**不要求本次做多线程。** 先量耗时：超过100–150ms的预测显示轻量计算状态、节流并缓存；要下放后台时只用隔离纯数据快照和线程安全模块，禁止工作线程改场景树。结果仍必须确定且无资源、存档、RNG副作用。

## 12.4 新美术不污染存档

建筑外观、配件位置、图层偏好不进入经济状态。视觉小变体使用独立稳定散列，以世界种子、建筑ID和美术版本选择；不消耗现有开局／招标／事件RNG。

默认继续兼容schema4经济数据；新显示设置单独保存。0.3.0用独立用户目录，首次复制导入0.2.1并校验，原文件不修改；确需schema迁移时有备份与迁移记录。旧城不会重抽起源、运营商、槽形或方案，也不追发章节奖励。

# 13｜性能与发布目标：先有预算，再谈手机版

以下全是**0.3.0目标预算，不是当前实测性能**。

| 项目 | 目标 | 超标时先做什么 |
|---|---|---|
| 世界纹理内存 | 目标≤48MiB，硬审查线64MiB，不含字库缓存 | 降运行尺寸、拆高低细节，不降UI字号 |
| UI／标注 | 普通画面最多12个标签；选中才展开关系 | 合并同类标记，保留可查看全部 |
| 预测响应 | 缓存命中≤50ms；未缓存p95目标≤200ms | 节流、减少复制、可取消的排队；超时有状态不冻界面 |
| 渲染 | Mac目标60fps；手机至少稳定30fps，较强设备60fps | 优先减少粒子、阴影、装饰；不得删主要图层信息 |
| 资源加载 | 不在每次选建筑时同步解码大图 | 分组预载、图集、懒加载次要详情 |
| 装饰动画 | 只更新可见且在运行者 | 静态帧替代，不伪造运行 |

参考纹理成本：未压缩RGBA8 2048²约16MiB，完整mipmap约21.33MiB；两页约42.67MiB。PNG磁盘变小不等于运行内存变小。[R5]

发布记录必须写设备、分辨率、画质、规模、帧时间分布与长时温升。Mac Retina／触控板和至少一台iPhone、未来一台Android的实际结果分开写；没有证据的格子写未测。现有0.2.1文档本来就明确Mac/触控板未做真机验收，不能继承为本次通过。[B1]

# 14｜执行顺序、责任和规模

这是同一版开发的工序，不向用户交付多份碎片游戏。

| 包 | 交付物 | 依赖 | 主责 | 量级估算 |
|---|---|---|---|---|
| W00 | 固定原包哈希、旧档与图层数据口径 | 无 | 开发 | 0.5–1人日 |
| W01 | Theme、响应式Shell、输入与决策暂停解耦 | W00 | 开发 | 3–5人日 |
| W02 | 三母版、十主体、装饰与配件整理 | W00 | AI素材制作＋整理 | 6–10人日 |
| W03 | 镜头、地形连接、精灵挂点与动态层 | W01，W02可并行供素材 | 开发＋技术美术 | 4–6人日 |
| W04 | 具体服务／环境／热／就业／资源／组织图层 | W00、W01 | 开发 | 4–6人日 |
| W05 | 选址、投标、换方案、政策共用地图工作台 | W01、W04 | 开发 | 3–5人日 |
| W06 | 目标／建成反馈、完整详情与触摸完善 | W03、W05 | 开发 | 2–4人日 |
| W07 | 旧档、画面、真机与完整打包 | W02–W06 | 开发＋实机检查 | 3–5人日 |

总量约25.5–42人日，仅为排期估算，不是固定报价或“AI几小时全部做完”的承诺。部分工作可并行，日历工期取决于实际投入、素材返工和设备可用性；**用户无需承担这些开发职责**。

缺资源时，优先后置高细节装饰变体、额外配件与非必要音效。不能后置十主体识别、服务语义、投标看地图、触摸确认、防误操作、来源账和旧档安全。

保留一个可启动工程，内部增量提交、随时可回退；开发用开关不变成用户面对的B/C多个产品。

# 15｜0.3.0验收：检查成品使用质量，不要求用户证明概念

完整可打勾清单见 `specs/03_ACCEPTANCE.md`。下列均为发布要求，而不是已经通过。

1. 十类建筑在默认缩放和无名称下可区分；河、岸、路连贯；无AI假透明、错视角、镂空墙。
2. 新城默认看得到登陆点和周围可规划区域，不再是一小撮城漂在大片空底中。
3. 医疗、教育、购物、休闲分别与真实容量分配一致；不使用“最好两项”混色。
4. 场的来源、局部聚合和实际效果可查询；无数据、零值、负值、未获容量互不混淆。
5. 方案比较时地图始终在场；切卡看得见受益者和代价；取消免费且候选不重抽。
6. 预测前后财政、资源、RNG、tick、存档不变；过期结果不被当作最新提交依据。
7. 旧版投标暂停语义保留；非模态界面不偷偷加速本地时间。
8. 手机紧凑布局没有三列小字长卡、没有必须hover才能看见的关键信息；拖动与缩放不会落楼。
9. 正文、重要图标、对比、字号放大、安全区均达标；彩色信息有非颜色线索。
10. 停工没有工作烟／风轮；建成预计与首次运营实际结果分开；成功提示对应真正完成的成果。
11. 导入0.2.1旧城保留全部经营关系，不改原档；所有40 Bonus／12政策仍有入口和解释。
12. 工程只有一个0.3.0入口、一个当前Mac包、对应源码及素材清单；移动检查单列未完成项。

不得用“新增76个素材任务、多个页面和N项断言”给趣味打分。验收的目的只是确保这次真的把玩家要用的东西做完整，而不是继续让玩家替程序猜含义。
