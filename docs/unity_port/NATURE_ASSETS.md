# Dynamic city nature resources

The dynamic Unity city uses six models from Quaternius' free **Stylized Nature MegaKit Standard**: `CommonTree_3`, `CommonTree_5`, `Pine_5`, `Bush_Common`, `Rock_Medium_1`, and `Rock_Medium_2`. The official archive was obtained through the free download flow on 2026-10-14. The Standard archive's unmodified `License_Standard.txt` is included in `Assets/StreamingAssets/ThirdPartyNotices/Quaternius-Stylized-Nature-License_Standard.txt`.

Official provenance: [Quaternius pack page](https://quaternius.com/packs/stylizednaturemegakit.html), [official itch.io download and CC0 listing](https://quaternius.itch.io/stylized-nature-megakit). The included Standard license declares CC0 1.0; these selected third-party resources are distinct from the project's original Hero Valley assets and their project-specific license.

Only the six glTF files and their required external buffers/textures are included under `Assets/Resources/CityNature/Quaternius` (18 files, 11,898,674 source bytes). Source geometry files are unmodified; runtime display copies receive the crown adjustments described below. Each model is imported by the installed official glTFast Editor importer in a URP-configured script domain. `CityNatureAssets.Prepare()` configures external texture assets before reimport: all textures at 512 maximum, mipmaps and compression enabled, readable textures disabled. External images are shared across models. Alpha mipmaps preserve silhouette coverage at the shared cutoff of 0.14. Source samplers use linear/mip-linear filters, which official glTFast maps to trilinear sampling. Normal maps retain the normal-map import type; glTF `MASK`, cutoff and double-sided material settings remain the official importer's responsibility.

There are three shared tree meshes and three shared detail meshes at runtime. Each mesh is assembled once per variant from official imported mesh/node transforms; instances use grouped material batches of at most 1,023 matrices. The combined runtime geometry releases its CPU mesh copy. This changes presentation only: detached snapshot terrain, seed and parcel state determine stable placements, and the simulation RNG/save/economy are never accessed. Forest candidates remain cached across parcel updates. Broadleaf trees predominate; occasional pines, canopy-width variation, staggered jitter and clustered density soften the forest boundaries. Sparse bank/hill shrubs and rocks follow the same parcel clearing. Source hill cells also place a few overlapping rock slabs at the crest and downhill shoulder sampled from the shared terrain surface.

The first real Player screenshots showed dark, noisy leaves and sparse tall trunks. The display copies use rounded crown normals, slightly deeper/wider crowns and denser staggered placements. `MET/City/Canopy` supplies a shared sage/olive palette with source RGB limited to ±8% brightness variation and a small stable whole-tree tint. Direct inspection shows that the broadleaf PNG is principally a flat color swatch: its fine leaf shapes come from the imported geometry, not painted leaf detail. The original PNG alpha is retained in all passes. A wrapped directional light and restrained ambient fill shade the crown without per-leaf self-shadow/specular noise; the official URP alpha-clipped ShadowCaster still casts the forest silhouette onto the ground. Forward, shadow and depth passes support GPU instancing. Serialized Resources material templates retain the shader in Player builds. The original glTF, buffer and image files stay unmodified.

This document records provenance and implementation choices. Actual Unity import, Player visuals and measured memory/performance belong in `FULL_MIGRATION.md`; source checks alone do not establish those results.

Intermediate Player captures rejected two mistakes: a dark flat crown in visual.4 and insufficient volume in visual.5. The final visual.6 display uses ellipsoidal normals that point up at the top, sideways at the rim and down underneath, with 12% original leaf normal retained. A continuous height/interior vertex gradient shades the lower crown without random dark spots. The canopy uses directly tuned shader working values: removing the explicit `.linear` operation brightened this material. This visual correction does not establish that all Color properties undergo an automatic conversion. Unity's current [SetColor documentation](https://docs.unity.com/en-us/engine/6000.5/script-reference/unityengine/material/setcolor) restricts that conversion to properties with the specified `[HDR]` / `[Gamma]` attributes; our ordinary URP surface materials retain their explicit sRGB-to-linear transform. Final appearance is documented by actual Player captures, not the predicted color formulas used during iteration.

## Original ground albedo

`Assets/Resources/CityTerrain/HandpaintedGrass-v1.png` was generated with the built-in imagegen tool on 2026-10-14 for this project. It is an original candidate ground albedo, not extracted from Civilization VI. The production brief was a seamless overhead hand-painted olive/sage grass material: broad grass clumps, crisp smaller blades, sparse ochre soil and pale mineral flecks, flat diffuse illumination, no cast shadows, ambient occlusion, scene objects, horizon, border or text. The generated file is retained without image post-processing; the terrain shader applies world-space repetition, biome tint and slope/river masks.

The art brief requested a 2048-square material; the actual generated image is 1254×1254 pixels (3,506,006 bytes). Unity imports at maximum 2048, sRGB, compressed, mipmapped, trilinear and 8x anisotropic filtering, with no CPU-readable texture copy. Visual acceptance must use the running terrain, including tiling and distant mip behavior.

## Chinese UI font

The UI now uses a static Noto Sans SC Regular (weight 400) instance produced by `tools/build_city_font.py` with fontTools from the preserved upstream variable font in `assets/fonts`. That variable font's default weight is 100 (Thin). The static font and original retain the supplied SIL Open Font License. `tools/sync_unity_content.py` preserves the static resource instead of re-copying the variable font into the Player. The smaller file is a packaging improvement; runtime memory and readability still require actual Player measurement.

`Assets/Resources/CityTerrain/HandpaintedRock-v1.png` is a second original imagegen material from the same date. Its brief calls for a seamless square flat albedo of broad interlocking warm-gray limestone planes, slate-gray crevices and restrained ochre ledges, with fine detail subordinate to readable stone shapes. It excludes vegetation, objects, grids, borders, granular speckles and strong repeating stripes. The generated 1254×1254 image is used unchanged. The runtime shader projects it along three world axes according to slope normal, preventing texture stretch on steep rock faces; the ground and rock maps have separate scale and weights.

## Medium-scale settlement groups

The 2026-10-14 user feedback changes the emphasis from large individual objects to recognizable building groups. The initial 68% / 82% scale was shown in a native Player capture; the user requested slightly larger primary buildings with stronger differences between groups. The following candidate uses 74% for ordinary primary models and 86% for the hospital, secondary school and power plant. This is a renderer-only scale applied to the existing registry models; it does not multiply capacity, population, production, construction cost or simulation entities.

The main building keeps its authored silhouette. A small combined mesh supplies use-specific low wings: homes and service wings, longer industrial sheds, a sparse campus wing, or a field shed. Agricultural rows and school grounds continue to reflect their registered use. Small infill forms short street-facing groups with open gaps instead of a continuous ring of roofs. Perimeter lanes and inter-plot connectors share the models' 30-degree frame, but perimeter lanes have lower width/contrast. Registered identity, actual operator/slot state and source information remain accessible through the UI. The diagnostics distinguish stable infill nodes, actual roofed volumes and open courts; node count is not house count.

Nearby hill cells now share a ridge direction derived from their positions; separate hill-cell domes are not added together. Broad footslopes and lower shoulders surround the crest. The river retains its source cell order/elevations while low-frequency width and bend-dependent bank profiles shape its visible corridor. River-distance queries avoid calculating the bank profile; bend influence is blended in world space for bank callers. Forest height is 0.52–0.82 world units before edge scaling (70–100% by density), with narrower crowns and smaller hill outcrops. Ground texture and close-range bump strength are reduced so landform, forest and settlement silhouettes carry the strategic view. Actual screenshots and remaining visual gaps are recorded separately in FULL_MIGRATION.md.

The following visual.12 candidate keeps the user-selected model scales. Ground beneath a group is now a smaller use-specific forecourt or work apron; agriculture and parks retain the actual ground. Open infill nodes retain their source identity without drawing a green box and an access line for every node. Source-related connections meet a single set of plot approaches instead of repeating that plot's entrance in each connector. The road ribbon joins both segment directions at corners. The rejected visual.10 intermediate had visible triangular gaps from back-facing corner triangles, even though its functional validation passed; The visual.11 correction removed the corner reversal but retained road/ground intersections inside faces. The final visual.12 roads are clipped to the actual visible ground triangles and raised from those planes; shared courts sit slightly above the street surface. Final visual evidence comes from the corrected Player.

Terrain uses a narrower continuous ridge profile with uneven flanks and, for longer connected ridges, a lowered saddle. Steep slopes expose warmer rock planes; the grass texture contributes less broad mottling, with small directional strokes fading by screen-space derivatives. The canopy's working palette shifts from gray olive toward green. These changes reuse the existing textures and source nature meshes, without adding texture maps, simulation terrain types, or runtime geometry on camera zoom.

The visual.13 settlement ground groups adjacent occupied plots and fits a shared gentle plane from their natural surface heights, limiting the plane gradient to 0.08. Smooth local corrections level the main footprints; overlapping corner weights are blended continuously. At the river, the grade fades between 0.10 and 0.82 world units beyond the visible shore, leaving water and the immediate bank unchanged. A narrower initial fade produced a platform-like cliff and was rejected after native inspection. Source elevation data and simulation state remain unchanged. Ground signatures include the plot center and eight surrounding samples so affected wings, courts and approaches update with terrain; stable terrain remains reused. Final captures and independent reviews are recorded in FULL_MIGRATION.md.

## visual.15: natural slopes, same-cell occupancy and surface families

This version supersedes the visual.13/14 neighborhood grading described above. `HeightAt` reads the natural generated surface, and occupied buildings no longer enter the terrain cache key. The main model uses a local foundation; on steep sites it searches for a less uneven position inside the same source hex, including the full footprint and entry. Low wings and annexes have their own ground ranges and supports. The terrain mesh, collision surface and source heights are not leveled for a neighborhood.

Main/wing footprints, usable entrances, field patches, actual streets and annexes determine visual occupancy. Candidate annex positions must be reachable from the main entrance through the same visibility graph used to draw their paths. Farm rows prefer the side of their source plot and reserve their actual ground area; they no longer occupy the front entrance. Courts reserve space against nature while allowing paths. Nature requests keep their seeded identity, size and orientation: safe originals are retained first, then obstructed trees, shrubs and rocks search for free space inside their original hex. Decorative instances are omitted only after no suitable space is found. Rebuilding the same actual/forecast plan reproduces the same positions; layout signatures cache both pathfinding and nature uploads.

Only sufficiently related adjacent completed buildings draw shared roads: presentation `relation >= .12`, or the same operator with `relation >= .04`. Relation comes from the existing employment/service/resource records; the cutoff is a visual density choice, not a new gameplay road rule. Mature tier or adjacency alone no longer draws a street. Connected entrances share path segments, degree-two bends use sampled curves, and meeting mouths receive rounded junctions. Source plan identities and relation information remain available.

`tools/build_city_surface_styles.py` draws six original, deterministic 512×512 albedos: meadow, forest litter, dry turf, compacted dirt road, staggered stone paving and gravel road. They are parameterized project artwork under `LicenseRef-MET-Project-Original`, not new CC0 assets or an image-model-only pipeline. Three ground maps blend using existing forest, dry-ground, river and slope conditions; the existing original rock material remains the fourth ground family. Three road materials use world-space triplanar projection, including steep support faces. Mipmaps/filtering remain enabled and no per-building texture copies are made.

The first v15 capture had repeated large grass spots and overly pale roads; that intermediate was rejected. The current patterns use smaller grass strokes, restrained dry-soil marks and darker paving. Actual import, final native images, road/field placement checks and performance belong in [FULL_MIGRATION.md](FULL_MIGRATION.md), rather than being implied by this implementation description.

## visual.16: simple building rings and six-direction connections

The user's subsequent request replaces the v15 shortest-tree-only parcel layout with one complete rounded loop around each completed main building. The loop follows its actual rectangular footprint with sampled corner arcs and the existing natural ground; its buffer narrows where needed to fit dry space inside the source hex. Six neighbor directions are projected from the main building centre onto this loop. Active shared roads reuse those exact world-space ring vertices and pass through the corresponding shared-edge midpoint.

Main entrances and roofed infill use short obstacle-aware branches to join the loop. Wings, side fields and infill reserve both the loop and its short outgoing corridors before choosing empty positions; nature uses the final complete paths. The earlier close-relation filter still limits which adjacent plots connect. The simple version does not promise traffic, lane markings or a simulated road network. Actual loop/exit checks and screenshots are recorded with the v16 native evidence.
