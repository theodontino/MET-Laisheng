日期：2026-10-30。适用于现有 Unity MET 的 HUD、管理页、建筑星图、科技、生产物流、施工、奖励及 Bonus 装配。

本文区分**当前事实、v1 开发要求、后续建议**。规范不证明现有 UI 已完成验收，不授权修改玩法、价格、DP、存档规则或整体重写。本轮只新增文档，不启动游戏、不提交推送、不修改运行代码。

## 2. v1 要求：技术与职责边界

- 已有 Toolkit 页面继续使用 UXML、USS、View；复用 CivicUI 和现有模板。已有 uGUI 按需维护，不为技术一致性整体迁移。
- 不引入 Web 重写，不用 HTML 模拟画面代替 Unity 验收。
- 数据路径统一为：**核心查询/报价 → 展示模型 → View → 用户意图 → Runtime 命令 → 核心复验 → 提交快照刷新**。
- View 不修改库存、RNG、奖励、施工、实体或存档，不复制解锁与价格公式。
- 模型使用稳定对象 ID，不能用中文名称、列表序号或临时 UI 元素地址识别业务对象。
- CityInterface partial 可以继续承担适配职责；只在触及流程时拆分，不先造大型框架。当前并非全面独立 Presenter 架构。
- 科技全城共享、资源升级单建筑、奖励获得 Bonus、槽位承载 Bonus，分别展示。**解锁槽位不等于获得 Bonus。**
- 生活／公共／生产分类不得暗中改变实体身份或模拟规则。
- 每个任务只改一个可验收流程；视觉改动不得顺便调整平衡或地图美术。若错误来自核心，先列证据和修复范围。

## 3. v1 要求：视觉 token 与组件

延续深色半透明表面、细边框、克制青绿强调、短中文和语义图标，让城市保持主角。布局依据最新适用合同，不把不同版本的相互替代尺寸同时执行。

当前来源是 `CivicShell.uss`、`CivicUI.cs`、各专用窗口 USS，以及 uGUI 公共构造器。它们尚未统一为单一 token 库。历史 Godot token 文件不能冒充当前 Unity 主题。

1. 开工列出本页 token 来源：表面、边框、文字、强调、警告、错误、间距、字阶、控件尺寸、焦点、动效。
2. 通用值集中在共享样式或公共构造器，页面引用语义类/变量；禁止继续散落复制 RGB、字号、间距。可逐步引入共享 token 文件，不声称它已存在。
3. Toolkit/uGUI 同一语义若有双份绑定，维护映射表或生成来源。
4. 节点位置、连线和进度等几何值可以局部定义，但必须集中、命名并说明用途。
5. 新控件先查现有组件；变体用参数或 class 表达，不复制整页。
6. 字号由基础字阶与字体设置统一计算，不在渲染函数随意覆盖。
7. 图标沿用 `Assets/City/UI/CityIconCatalog.cs`、`Assets/Resources/CityIcons/` 和 `assets/ui/icons/met-civic-v1/` 原始资源，保持方形比例；缺图标时用短文本退化。
8. 字体来源为 `Assets/Resources/CityFonts/NotoSansSC.ttf`。字体、插画与图标保留来源和许可；程序化插画不得称为已验证的纯图像模型流水线。

| 组件 | 必须覆盖 |
| --- | --- |
| 按钮/节点 | 默认、悬停、焦点、按下、禁用、提交中；常规/主动作/破坏动作 |
| 指标 | 库存、流量、容量、比例；单位、分母、来源 |
| 奖励卡 | 可选、选中、不可领取、提交中、已领取 |
| 槽位 | 未解锁、施工中、空槽、已装配、不兼容 |
| 窗口/列表 | 正常、空、错误、只读、目标消失、数据更新 |
| 来源详情 | 展开、折叠、筛选无结果、分页 |

禁用必须解释原因，关键错误不能只存在于短暂 toast。

## 4. v1 要求：布局与中文

按第1节的现行呈现依据，以 **2560×1440 桌面全屏**为当前验收基线；本规范不额外引入不同窗口尺寸或移动端工作。

- 记录实际 Player 分辨率与显示模式，启动参数不是实际输出证据。
- UI 比例、字体和地图缩放相互独立，改变一项不得偷偷修改另两项。
- **建议测试矩阵：** UI 80/100/120% × 字体100/125/150%，共九组几何检查。真实截图至少覆盖默认、最大组合和发现问题的组合；最大组合实际点击关键确认。若设置实际支持档位不同，先报告再使用真实档位。
- 标题与确认区固定，正文滚动；费用、禁用原因和确认按钮始终可达。
- 用实际中文字体检查长标题、两行按钮、长错误、负数、大数和多来源内容，不能仅凭 RectTransform 尺寸为正判断文字可见。
- 不靠无限缩小字体解决溢出。摘要可以截断，但完整内容可主动展开。
- 未结算和无记录分别写清楚，不用虚假零值代替。

## 5. v1 要求：星图规范

- 节点、路线和依赖来自核心数据；不得根据画法新增 AND/OR 规则。
- 选中状态独立于可用、锁定、施工、完成状态。
- 连线连接节点边界，缩放及布局变化后重算；位于节点背后，不截获点击，不穿过名称。
- 旁路、交叉与方向有图例或文字说明。
- 节点显示名称、类型、状态；详情显示科技条件、依赖、资源费用、DP 使用/容量、CP/施工和生效时点。
- 节点支持键盘到达；选择后保持可见，确认区不随详情滚走。
- 换建筑或重开重新报价。
- 未定义价格的后续节点明确“未开放”，不得猜值。
- 槽位完成显示“空槽，需持有兼容 Bonus”，不暗示自动发卡。

## 6. v1 要求：状态与文案

下表是表达模式，不定义新玩法。括号中的实际条件、费用与效果必须来自核心/配置。

| 状态 | 表达要求 |
| --- | --- |
| 科技不足 | 所需科技、当前与要求等级；标明全城作用域 |
| 依赖不足 | 前置节点及“全部/任一”，依据核心 |
| 资源不足 | 持有、需要、差额；累计条件不能误写成再次扣费 |
| 可以开工 | 支付时点、施工要求、生效时点 |
| 施工中/受阻 | 真实进度及缺料、缺电或能力原因，不编倒计时 |
| 已完成 | 实际生效状态，不能仍可重复购买 |
| 可领取/已领取 | 选中只是预览，命令成功后才获得奖励 |
| 空槽/可装配 | 槽类型、兼容性、持有份数和消耗 |
| 只读/陈旧 | 明确原因；变化后要求重新确认 |

库存用绝对量，资源流用 `/月`，电力是容量，CP 工作量与 `CP/月` 分开。实际与预测、基线与方案必须有来源标签；比较来自同一步。环境面积图使用全城地块分母。保留服务来源、运营方和槽位历史，区分服务可达与实际分配容量。

效果数值来自核心摘要或报价，不扩大手写数值文案。当前 `CityWildStar.cs` 的 `WildNodeEffect` 存在字面说明，触及效果时必须核对，不能冒称已解决。旧 Beta 装配与 Wild 节点取消可能存在不同返还语义，不能用一条通用退款文案覆盖。

## 7. v1 要求：命令与快照

- 一次明确确认只发一次命令；鼠标、键盘和回调共用提交门禁。
- 提交捕获目标、选项、版本及上下文，立即显示提交态，用 try/finally 或等效方式可靠恢复。
- Runtime 在 Flush 后复验目标、资格、库存、费用与预览版本。
- 报价变化必须刷新并重新确认，不能静默按新价格付款。
- 核心也要拒绝重复购买/领奖，不能只靠按钮禁用。
- 非法操作不得部分扣发资源或改奖励/RNG；比较前后业务快照。
- 独立生命周期时间戳变化单独解释，不能掩盖业务差异。
- hover、展开、切页与关闭重开不得抽奖、重掷或消耗资源。
- 预测只操作 detached 副本，不触碰玩家状态。

现状差距：`CityToolkitUpgrade.cs` 有版本比较，`CityWildStar.cs` 未见同等显式预览版本比较。不得写“全系统已满足”，后续触及星图提交时优先补齐。

## 8. v1 要求：输入与生命周期

- 沿用 KeyboardOwned/PointerOwned 和摄像机接线，不另建第二套全局输入。
- 同时检查 Toolkit picking 和 uGUI raycast：装饰不挡地图，窗口/滚动/模态必须挡住底层操作。
- Esc 一次只处理最上层：文本/解释/确认 → 操作窗或详情 → 页面 → 地图设置，避免 View 与全局各关一层。
- 中文输入法组合、搜索和文本焦点期间，不触发 P、L、Shift+L、空格等游戏快捷键。
- Tab/Shift+Tab 可到达操作，模态焦点不得落到底层。
- 关闭清除确认态、指针捕获及延迟 tooltip，恢复有效原焦点。
- 重开可恢复滚动/筛选，但必须刷新报价；换城或对象消失清空旧上下文。
- 订阅、调度器、回调及运行时 PanelSettings 明确所有者和释放时机；重开不得重复订阅。隐藏复用可保留一次订阅，销毁必须解绑或随整棵拥有的树释放，异步结果不能更新已关闭视图。

## 9. v1 要求：性能与可访问性

- 沿用 dirty、版本缓存和懒加载折叠；无变化不重建整树、不反复预测或加载资源。
- 鼠标按下至抬起期间不销毁目标按钮，输入刷新不丢文字或光标。
- 长列表先复用/分页，有测量证据再虚拟化。
- 保持现有默认60 FPS；同设备、存档、镜头与源码比较 UI 关闭、打开、滚动和反复开关。
- 模拟耗时、渲染帧间隔和 GC 分别记录，不把 headless 或软件 Vulkan 当 Mac GPU 结果。无来源的毫秒预算先测基线，不随意承诺。
- 状态不能只靠颜色；辅以文字、形状或图标。保留高对比和减少动态设置，焦点清楚，不闪烁催促确认。
- 信息有点击与键盘入口，不能仅靠悬停或声音。
- 当前普通解释合同两秒与 Civic 通用 tooltip 代码0.5秒需明确区分，不能宣称已统一；修改需单独说明。

## 10. v1 要求：存档隔离是启动门禁

依据 [默认存档审计](../wild/DEFAULT_SAVE_AUDIT_20261029.md)，过去测试确实写入默认存档，且备份漏掉实际 bundle-ID 目录。事故后 `.bak` 不能冒充运行前备份。

`CityRuntime` 优先使用 `MET_UNITY_SAVE_ROOT`；否则按模式使用 `Application.persistentDataPath` 或其 `Wild-G1` 子目录。显示设置也会写入 StorageRoot。命令成功、自动保存、失焦和退出均可能写盘。

运行前必须：

1. 记录实际可执行文件、应用标识、company/product、模式、参数与相关进程，不为测试结束用户进程。
2. 核对真实默认路径、SavePath、`.bak/.tmp`、显示设置及其他持久化位置，不能按 App 名猜目录。
3. 保存运行前清单、mtime、大小与 SHA256；备份逐项校验，备份代码不能替代存档备份。
4. 使用唯一隔离根和测试应用标识，配置在测试副本中，不改变正式产品身份。
5. 核对普通启动、GUI 启动、重开和自动重启都继承隔离；父 shell 有变量不证明目标进程收到。
6. 无法在写入前证明隔离时停止启动，先修测试启动路径，不能启动后再发现默认档被写。
7. 运行后记录实际 StorageRoot/SavePath，退出后复核默认目录未被写入。
8. 若发现污染，保留现状、记录不确定性，不擅自覆盖或拿 `.bak` 回滚。

`tools/test_unity_city.sh` 与 `tools/run_wild_g0.command` 有隔离根传递，可作为起点，不证明所有启动方式安全。权限拒绝或等待时，不更换应用/输入途径绕过。操作结果不确定先查证，不重复点击。

## 11. v1 要求：开发与验收流程

1. 记录 HEAD、dirty 文件、允许修改范围和目标用户流程，保护并发改动。
2. 列模型、状态矩阵、token、命令与回滚边界。
3. 完成最小实现，针对性检查核心与重复命令。
4. 单列真实 Unity 编译/import，不能用 .NET 核心通过代替。
5. 完成存档隔离后启动实际 Player。
6. 保存截图、真实鼠标键盘步骤、前后业务状态和日志；测量期间冻结源码和资源。
7. 分别报告通过、失败、未执行与阻塞，不能空白默认通过。

每个受影响流程至少验证：

- 打开、查看条件及来源、选择、确认成功。
- 连续点击/确认只扣发一次。
- 禁用原因、陈旧报价、目标失效。
- Esc、焦点、地图穿透、最大字号。
- 关闭重开及持久化后状态一致。
- 奖励只发选中项、真实拒领条件（如适用的满仓）；装配遵循库存、槽资格和实际返还规则。
- 科技符合全城作用域，单建筑升级不误改其他楼。

**编译不等于运行；运行不等于真实点击；截图不等于业务正确。**回调、注入事件、Editor 夹具、Player 真实输入分别标注，HTML 截图不得替代 Unity。预置资源的夹具必须列出预置，不证明自然游玩可达性或平衡。

交接上下文报告上轮177项及回归、Unity编译和macOS构建签名通过，但真实 UI 启动出现 `Transport closed`，购买、领奖、重复点击、装配及重开未验。这是交接状态，不是本文复验结果；仓库旧轮次115项等证据不得改标成177项或本轮通过。历史1920×1080画面不能冒充当前2K验收。

回滚只处理本轮文件/改动块，核对 hash 防止覆盖并发修改。代码回滚与玩家存档恢复分开；恢复需明确版本、来源与授权，并保留当前副本。纯文档任务不顺便构建或发布。

## 12. Codex 任务与验收模板

```text
目标：完成 MET 中［一个用户流程］。
依据：本规范、［对应玩法合同与当前用户决定］。
基线：分支、HEAD、dirty 清单。
允许修改：［文件/组件］；禁止修改：［玩法、价格、存档等］。
技术：复用［现有 View/UXML/USS/CivicUI/uGUI］。
数据：［查询、报价、对象ID、版本、Runtime命令］。
状态：正常、空、锁定、施工、成功、只读、过期、目标消失。
样式：［token 来源、必要的新变体］。
启动：核实实际存档路径、隔离应用标识、重启路径及前后清单。
验收：现行全屏基线、独立缩放、真实点击/键盘、重复确认、重开、穿透。
证据：核心、编译、回调、截图、真实输入、自然平衡分别报告。
回滚：目标文件/hash；保护其他未提交工作。
交付：结果、证据、未验与阻塞；遵守本任务发布限制。
```

| 验收字段 | 必填内容 |

## 13. 后续建议与待决定事项

最小迁移顺序：先选现有星图或升级流程补齐版本校验和状态文案，再收敛该流程的视觉 token，随后复用到奖励与装配。只有规模或性能证据需要时，再抽离更大 Presenter、引入列表虚拟化。每一步独立验收和回滚，不建立平行模拟。

不需要重新决定引擎或整体重写。后续只需确认存在产品冲突的具体事项：当前 Civic 布局与旧合同的位置差异、tooltip 时机，以及未定义的后续星图节点规则。没有决定前不由 UI 开发猜价格或玩法。

本规范的完成仅表示文档交付；不表示上述现存代码债务已经修复，也不表示真实 Player 验收完成。
