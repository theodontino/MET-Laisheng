# Beta 界面与地图重置合同

依据：2026-10-03 用户最新界面诊断、四层模型、实体差分方案，以及随后明确的“pre-1.0 默认全屏，最低 1080p；不用测试不同大小窗口”。这是实施约束；实际结果另记，不能将本文件当作验收通过。

## 目标与边界

能扫：常驻信息图形化，三秒内辨认城市状态。分层：按必要状态、被动感知、当前操作、深入研究归位。一个动词：每个情境面板只突出一个主动作，位置固定；详情入口保持低权重。

延续同一 Beta 模拟器、时间/DT、奖励、主题、许可、来源、存档与随机流。展示只读快照，不为图形效果创造实体、资源或玩法。当前 Beta 的年度/人口奖励与主题委任、DT 归零命名规则优先于用户诊断中引用的旧版“主要委托/地区目标”。DT 是发展预算，不是财政通货。

整个 pre-1.0 默认桌面全屏，最低支持分辨率为 **1920×1080**。本轮仅以此基准进行原生窗口验收，不安排小窗口或不同分辨率适配/测试。移动端继续不在开发、打包、验收范围。

## 四层准入

| 层 | 准入与内容 | 形态 |
| --- | --- | --- |
| L0 环境 | 仅 DT 余额、人口数、粮食库存、时间控制器（来生周期/暂停/速度） | 图标＋数字胶囊，常驻；不能混入收支、材料、电力、运营商、规则明细 |
| L1 状态 | 最多两条严重警报，其余收进计数入口；一张已接主题进度卡；当前分析图层图例 | 小卡片贴边，绿正常、黄注意、红待处理；细节按需打开 |
| L2 情境 | 选中建筑、正在选址的地块 | 大图、最多三个图形指标、一个突出主动作；其他收进“详情 ›” |
| L3 档案 | 预算/流水、人口/就业/服务、市场/订单/成交、政策、升级树、运营商投标、Bonus/槽位/蓝图、来源/规则/历史 | 主动打开现有工作台或档案面板；允许文字、表格、比较和管理 |

用户在选址处提到投标比较，也明确“运营商 / 升级树 / 政策 / 市场全部 L3”。统一解释为：L2 有“比较投标 ›”主入口，实际候选比较与付费确认在 L3。图标配可读悬停说明与焦点说明，不能靠隐藏名称降低可用性。

### 次级与三级页面追加要求

用户看过首轮实现后认可主界面，但指出次级、次次级页面“还是很丑，全是字，缺乏视觉引导”。据此保留已认可的主界面与地图，继续重做 L3 阅读结构。允许文字和表格不等于允许长文平铺；不能仅给旧段落添加边框或图标。

- 档案入口以图标、当前状态和清楚的主题卡导航；所有层级保留可辨的标题、面包屑和返回路径。
- 资源、人口、预算先呈现实际流向、库存／住房／岗位容量、需求覆盖和来源贡献，再进入完整记录。历史图只能使用已有历史；未知值不画成零，跨单位数值不共用伪造比例尺。
- 建筑档案先呈现建筑身份、实际生产关系或住户／服务容量；槽位和成长轨道可视化，完整 Rule、Field 与账本按需展开。
- 成长与升级用建筑图像和真实能力差分帮助比较；施工展示共享 CP 和各工程实际进度。
- 主题展示阶段轨道与实际目标进度；奖励横向比较副本／研究和关键效果，规则长文可展开，FIFO 及候选持久化不变。
- 市场先报价与真实运力，再选择资源／方向／数量／限价并确认；显式处理负价的现金方向。订单和成交可对齐比较，不创造不存在的价格历史。
- 政策同槽互斥关系和真实更换代价可辨；预测来自已有 planner，不以装饰图形暗示不存在的收益。

共享视觉组件只接受展示数据，不访问游戏状态或随机流。新的页面仍在全屏 1920×1080 验收；不增加移动端或多窗口适配范围。

### 建设影响与整体界面缩放

2026-10-05 追加：整体界面支持 80%／100%／120%，与地图滚轮缩放及原有字号设置独立。仍然使用同一 1920×1080 全屏验收；界面缩放不是小窗口支持。

投标比较以三家运营者的紧凑卡、同一比例尺的建设前后供需图、当前库存容量条、电力供需和环境变化呈现。默认字号下主要影响直接可见；完整投入、运行、规则和来源进入详情。当前库存不使用建成后的预测库存冒充；月率、电力能力、住房容量和污染场强不能共用数值轴。库存可撑月数仅为当前全城库存除以预测净消耗的参考，不保证局部可达或后续经营结果。没有消费需求时，产出占需求比例显示不可用。

建设前后均来自同一城市版本、同一下一结算周期，分别表示不建设和假定方案已完工。地图提供现状预测／建成后切换，并标明来源；保留未建设建筑的规划幻影，不提前改变城市实体或几何。差分将供给／服务增加与消耗／竞争／环境负担分开标色，同格并存用斜纹表示；不把不同单位加成一个分数。电力按现有全城比例分配规则表达，不暗示空间电网。

`L` 循环至下一图层，`Shift+L` 返回上一图层。有效建设预测时加入本次改变；输入框、弹窗及档案工作台持有键盘输入时不循环地图。资源、电力、污染和差分图也可从比较中的图形入口直接打开。预测选择、界面缩放和图层切换不得修改 Gameplay、RNG、钱包、存档或实体；仅提交主动作才购买方案。

## 建筑差分

| 状态/类型 | L2 | 主动作 |
| --- | --- | --- |
| 施工 | 建筑预览、环形进度、预计剩余本地时间；材料/电力不足时如实显示停滞 | 调整优先级 |
| 住宅 | 入住容量环、宜居环、人口；健康/幸福/教育细值及口粮率去档案 | 升级；到顶后提供实际可用的管理入口 |
| 生产 | 输出资源图标与数量、运行率环、瓶颈状态；投入清单/维护/详细效率去档案 | 升级；到顶后提供实际可用的管理入口 |
| 服务 | 按真实服务类型显示服务人数/容量、覆盖或运行指标，不套住宅/工厂字段 | 升级或服务管理 |
| 物流 | 粮食/材料/制成品三条库存容量条 | 打开市场 |
| 暂停 | 整卡状态色、暂停徽章，收起正常态指标 | 恢复 |
| 异常 | 状态色、明确瓶颈；收起无关正常字段 | 定位/处理真实缺口；不能把不可恢复的短缺伪装成“恢复” |

T1 混合建筑按主用途决定首屏，其他能力仍在档案中可查。所有原有来源、数值、槽位、安装、供人优先级、运行暂停、拆除入口必须可达，不能用删功能实现简洁。

## 地块选址

空地在地图上显示就地气泡，不再挤入建筑 Inspector。最多两项与当前起点有关的预计产出图标、一个风险点、一行造价/材料/施工量，以及“比较投标 ›”。气泡跟随地块/镜头，避开屏幕边缘；不挡住选中地块。预测必须有来源与单位，不伪造精确收益。

## 主题与警报

- 未选择主题时不在 HUD 显示空任务卡；通过可发现的工作台入口选择。
- 进行中显示一张主题卡、进度条、真实阶段信息；只有真实期限存在才显示倒计时，不能凭空制造截止日期。
- 进度超过 90% 时黄色提示，轻微呼吸遵守减少动态设置。
- 完成待领取时金色和“领取”动作；声音只在实际状态转换时触发，不在刷新或读档反复播放。
- 材料为零但没有工程/消费者时，不应仅凭库存为零判定红警。红警对应正在发生的断供/停工，点击直达真实问题来源；最多两条，超出收进数量入口。
- 黄色低库存只改变相应指标语义色；蓝色消息不进 HUD，进城市档案。

主动操作的结果与自动城市消息分开处理：支付、交付、命名等命令失败时，必须立刻给出可见原因；短时命令反馈不增加常驻 HUD 项，也不因打开或刷新 L3 而消失。主题奖励入口须遵守已有奖励队列顺序，明确显示前序奖励，不能让主题偏好造成无法领取。

## 地图视觉

参考优先级：Against the Storm 的委托/顶栏组织；Frostpunk 的资源条与氛围；Anno 1800 的建筑情境卡；CK3/RimWorld 的可定位告警。地图采用 Civilization 式明确六角地格与地貌/资源辨识逻辑。实现使用原创程序形状和本项目可分发资产，不提取参考游戏资源。

降低地形写实噪声，建立清楚的地貌色块、轮廓与资源符号；水系和高程有真实来源，地图命中与选择不漂移。建筑主体缩小到与地格协调的尺度，留出庭院/道路/填充带；Tier 与功能继续可辨。统一附属房/店铺/仓棚/街树模块与跨格连接，不为每种邻接制作大体积专用建筑。停工/暂停不能伪造冒烟和运作。

## 验收要求

实际原生全屏 1920×1080 查看地图、各类 L2、选址与 L3；通过真实按钮验证主动作、详情、返回、警报定位、暂停/停止补交、奖励领取。核对信息层级、遮挡、图形指标含义、建筑/地貌尺度与相邻发展区衔接。

保留展示只读与来源正确性检查，执行受影响的核心回归。性能使用同场景前后比较，软件渲染不冒充目标 GPU 验收。本轮不测试不同窗口尺寸，也不把旧 900×620 截图算作当前验收。
