# MET 下一 Beta · Codex 设计交接 v3

> 文档版本 v3，不是已完成的软件版本。交付内容是产品规则、参数初稿、内容草案、界面要求和验收合同；没有修改或推送游戏代码。

## 开工入口

按顺序阅读：

1. `01_BETA_SPEC.md`：最终用户决定、时间与奖励状态机、范围。
2. `02_PARAMETERS.json`：来生正典历法、可调整的 Beta 数值、单位与状态标签。
3. `03_CONTENT_DRAFT.md`：5个主题、15个阶段、15个事件、12张方案的两次升级、5栋定型建筑。
4. `04_UI_SPEC.md`：四层注意力模型、四种核心界面状态、城市声音。
5. `05_IMPLEMENTATION_AND_ACCEPTANCE.md`：源码落点、实现顺序、边界用例与交付证据。
6. `06_DECISIONS_AND_SOURCES.md`：旧稿废止表、来源、待验证项目。

`07_MATH_CHECKS.json` 是本次设计稿的单位换算检查，不是游戏测试结果。

## 证据与决策等级

- **[用户确定]**：本轮聊天中用户明确决定，实施时不得自行反向解释。
- **[正典]**：已经查到世界观原文，按来源使用。
- **[初值]**：设计者提出的可配置 Beta 初值；可先实现，但不得宣传为已验证的平衡。
- **[建议实现]**：为消除工程歧义提出的默认实现，不冒称用户逐条批准。
- **[发布前门禁]**：可以并行开发，但必须通过对应验收后才能宣称整版完成。
- **[展望]**：不写入本 Beta 的活动功能、玩家菜单或可用货币。

## 本轮完整游戏目标

让玩家主动决定：什么时候值得燃烧有限 DT，把一个来生殖民聚落推向下一阶段。建筑、库存、供给、年度构筑、主题委任和城市声音必须围绕这个决定服务。

在现有单 Block 游戏里完成一整轮，而不是另起切片 Demo。保留三级建筑、运营商槽轨、Rule/Field/Population/Allocation、贸易订单、来源可追溯的图层。新功能在这一游戏中整合。
