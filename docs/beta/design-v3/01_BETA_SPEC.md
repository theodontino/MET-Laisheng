# MET 下一 Beta · 时间、构筑与城市声音

**状态：可开工规格 v3；数值和内容中的“初值”尚未经真人试玩验证。**

## 1. 这版要带给玩家什么

[用户确定] 一座 Block 在大约五个来生年的高速发展预算里，从殖民起点成为有性格的功能城区。五年是初始 DT 能购买的额外时间，不是第5年强制死亡，也不是“必须在五年内塞满地图”。在线自然时间不会消耗 DT；线下和暂停不会推进城市。

主循环：

`看城市 → 建设/装配/准备库存 → 选择时间档 → 燃烧DT推进本地城市 → 年度/人口奖励与主题事件 → 调整构筑 → 实际DT归零 → 命名；已完成Commission则获得主题定型建筑 → 留城或独立重开`

[用户确定] 一个来生日36地球小时。游戏必须适配来生历，不再凭整齐程度虚构360日年或135日年。

## 2. 本轮范围与排除

**本轮做**：新时间/DT、在线外贸时间分离、年度和人口奖励、两年大周期、Commission主题及稀有重铸、重复Bonus、两次Bonus升级、DT归零收尾、命名、条件性奖励建筑、HUD与L2差分、建筑告警、市民泡泡、城市消息。

**本轮不做**：District、Reserve消费或恢复玩法、离线补算与离线奖励、跨局继承、人口阶层、组织总部成长/友好度、政治操纵与宗主国、全套宏观经济、移动端发布、全面美术重制、旧存档兼容。

奖励建筑可以叫“工会总部”等，但只是本Block的一栋数值地标，不等于加入跨区组织总部系统。

## 3. 正典历法与单位

[正典] 世界背景总档9.1–9.2采用 **6—12—144历法**：

| 单位 | 来生口径 | 地球等效长度 |
|---|---|---:|
| 日 | 民用24来生时 | 36地球小时 = 129,600秒 |
| 来生时 | 1/24日 | 90地球分钟 |
| 旬 | 6日 | 9地球日 |
| 月 | 12日 = 2旬 | 432地球小时 = 18地球日 |
| 季 | 36日 = 3月 | 54地球日 |
| 年 | 144日 = 12月 | 5,184地球小时 = 216地球日 |
| 大周期 | 2年 | 288来生日 |
| 基准额外预算 | 5年 | 720来生日 = 1,080地球日 |

**废止上一条助手声称的5日旬、15日月、135日年、9月一年。** 那些不是本次核到的正典。天文学总档与游戏前台精度不同：原文“约36小时”，游戏按用户决定精确取36小时；不增加恒星日/太阳日误差模拟，不添加月相循环玩法。

内部时长使用带单位的字段：`active_real_seconds`、`local_elapsed_seconds`、`offline_recorded_seconds`。本地秒以地球秒等效记长，避免“来生时”和“地球小时”混用。显示层才格式化来生年月日。

“旧经济小时→新来生月”只是一种迁移适配器：`economic_months = local_seconds / 1_555_200`。它保留许多产消比值，不证明整局平衡无需重调。

## 4. 时间与生命周期状态机

### 4.1 状态

| 状态 | 城市/移民/本地经济 | 外部市场自然时钟 | DT | 离线记录 |
|---|---|---|---|---|
| 在线运行×1 | 与现实等长推进 | 与现实等长推进 | 不扣 | 不增加 |
| 在线加速 | 按档位推进 | 只按真实活跃在线时长推进 | 按额外本地时间扣 | 不增加 |
| 手动/决策暂停 | 冻结 | 冻结 | 不扣 | 不增加 |
| 关闭/后台挂起 | 冻结，无补算 | 冻结 | 不扣不回 | 只记离开多久 |
| DT耗尽后继续 | 只可×1 | 只按活跃在线时间 | 维持0 | 同上 |

[用户确定] 离线只积累/记录时间，不发资源、DT、卡、事件、移民或任何其他奖励。Reserve只列展望，因此记录的离线时间在本Beta没有兑换或消费入口。

[建议实现] 切到后台/系统挂起停止加速，返回默认×1且先保持暂停，防止用户没有准备就继续烧DT。线上时长用单调时钟；UTC只用于离线长度记录。系统时钟回拨不得令离线记录为负或令玩法倒退。

### 4.2 DT预算

[初值] 初始75 DT，对应5来生年**额外**本地时间：

- 1 DT = 9.6来生日 = 345.6地球小时 = 1,244,160秒。
- 1来生年额外推进 = 15 DT；2年 = 30 DT。
- 不因历法从135日改成144日而重新改变玩家预算的“5年”目标。

对一个成功提交的时间段：

```text
local_dt = actual_active_real_dt * acceleration
extra_dt = max(0, local_dt - actual_active_real_dt)
dt_spent = extra_dt / seconds_per_DT
```

这是为额外时间付费。因此不同档位推进同一段日历时间，DT有极小的自然时间差，不宣称数学上完全相等；在这些高倍率下近似相同。

[用户确定] DT必须真实消耗至0才触发尾声。用剩余DT反推最后一段可推进时长，再提交状态并精确写0；不能“低于0.1就当死”，不能扣成负数再回滚时间。

审计所有旧DT入口：离线恢复、旧目标奖励、起源补充、报价重抽、重签、改槽、调试补给。**[建议实现]** 本Beta普通DT开销只保留加速与稀有委任重铸；报价重抽只付通货。普通城市目标和年度奖励不回血。调试补给必须标记非正常经营。

|---|---:|---:|---:|---:|---:|
| 常速 | 1 | 18地球日 | 216地球日 | 432地球日 | 1,080地球日 |
| 观察 | 5,184 | 5分钟 | 60分钟 | 120分钟 | 5小时 |
| 推进 | 25,920 | 1分钟 | 12分钟 | 24分钟 | 60分钟 |
| 燃烧 | 77,760 | 20秒 | 4分钟 | 8分钟 | 20分钟 |

[初值] 保留前面“1年/12分钟”和“1年/4分钟”的体感目标，按正典重新算倍率。表中不计暂停；不是对实际整局用时的保证。切换档位不提供独立数值奖励。

### 4.4 结算与边界

经济主步长**最大**1来生日（1/12经济月），不是强制每次跨一整天。在线×1也必须能提交小时间段；不得把旧代码的`round(h*1e6)`原样套到经济月上丢失小时间。

按下列边界拆步：DT耗尽、年/大周期、移民到达、施工竣工、已定义的任务时限、实际输入不足/仓容边界、等待玩家的事件。提交前发生错误则整段失败，不扣DT也不发奖励。

同一时间点的建议稳定顺序：本地/贸易实际账本 → 施工/迁入/人群重新安置 → 委任与人口阈值 → 年度及大周期奖励入队 → 扣除本段DT → 首次归零定格完成资格 → 暂停并统一呈现。

最后一段DT恰好完成Commission，算此前已完成；不可因遍历顺序不同错失定型奖励。

[建议实现] 年度奖励、大周期、必须选择的事件、DT归零硬停。人口奖励入队并轻提示，可配置合并到下一决策停点。缺电/缺料应依据实际运行中断与预测耗尽判断；默认只在从安全进入关键风险时刹车，加入去抖，不得每个tick重复强停。正常竣工/迁入不默认弹模态窗口。

## 5. 经济与施工的尺度适配

[初值] 现有率值优先改成“每来生月”而非重写所有金额：产消、维护、税率对应的流量、CP/月。库存、岗位、住房、容量、效率、Field读取阈值是不同量纲，不能一起乘432。

能源须分清供电能力和耗能累计；污染须分清即时场强和累计排放。服务容量是可同时分配的名额，不是每月再往人口里累加一次。教育/幸福响应、出生、移民、所有时限必须逐项重标单位。

基础4 CP/月；现有2.4–2.8 CP的T1约7.2–8.4来生日，5–6 CP的T2约15–18日，12–16 CP的T3约36–48日。均指独占4CP、满供能供材，无其他增益。

五年基础总额为240 CP，但不是240 CP必然都转成建筑：工程竞争、资源缺口、停工均扣实际效率。土木构筑通过现有料场/货运站与方案提高CP，不改DT时间成本。6–8CP/月普通后期、10–12CP/月土木路线只是目标区间，不作硬上限。

[初值] 初始18人口；每3来生月6人，按Local Time抵达；健康稳定群组自然增长候选3%/来生年。不能直接沿用旧每小时出生系数。人口是现有抽象群组，本Beta不加入儿童/成年劳动力延迟实体。

## 6. 外部市场：时钟不跟随DT，吞吐独立定量

[用户确定] 不冻结建筑/岗位/关系。DT加速本地生产、税收、维护、能耗、污染；外部供给按在线外部时间工作。移民明确例外，按Local Time。

三个口径分离：

1. `local_dt`：本地经济、施工、人口、年度、目标持续时间。
2. `external_dt`：真实活跃在线时间，控制市场压力自然回归。
3. `external_capacity_rate`：每真实在线小时的货运能力，决定本期成交上限。

```text
trade_budget = sum(running_freight_capacity_per_real_hour * utilization) * external_dt / 3600
```

交易总预算被订单共享；钱、库存、仓容、限价继续约束实际成交。交易对价格造成的压力仍由真实成交量驱动，不必等待市场自然时钟。

**[发布前门禁：贸易不得被时间换算意外删除]** 若把原货运站12单位/旧小时直接映成12单位/来生月，再让它只吃真实时间，一现实小时仅成交12/432≈0.0278单位，港务路线将失去可玩吞吐。这不是可以靠“先囤货”忽略的误差。

[初值/独立待测] 标准货运站先按120单位/真实在线小时（2单位/现实分钟）、市场压力回归时间常数15真实分钟测试。它不是正典也不是当前代码值，必须单独写配置并比较观察/推进/燃烧档下的进口、自给和出口路线。不得暗中加5%吞吐保底或把外部市场改用Local Time。

严格比例仍成立：同一单位本地时间的外部吞吐随A按1/A缩小；只是贸易绝对率有自己的单位，不再照抄生产的月率。贸易数量和价格自然回归须分别测，避免高倍下永远不成交或价格不变。

显示外部低速不等于报警。自给城市不用进口时，不因外部比例低而危险；按真实需求、缺口及库存告警。

## 7. 奖励节奏与许可

[用户确定] 普通构筑机会来自每个来生年与人口里程碑。两年Major Cycle作为大章节保留。

[建议实现] 每年来生年普通三选一；人口32/64/128/256各一次。人口里程碑按真实入住人口首次达标并保持1来生月确认，避免迁入大量无家可归人口刷奖；记录跨回落不重复。阈值与稳定时长均初值。

[建议实现] 大周期不再额外复制一份普通年度卡，负责两年总结、主题事件、阶段机会。改变其长度只是一个难度调节点；若要影响普通卡稀缺度，另调年度/人口奖励参数，不能偷改天文年长。

奖励实体统一入队，保存来源、候选和领取状态。同帧年度、人口、委任完成分别保留。候选不足3则2选1或1选1；0候选用已配置的小额通货补偿，不阻塞。fallback金额初值30，不回DT。

候选跨奖励可以重复，领取后副本增加；同一候选组默认不同名。已拥有或已部署不是从牌池过滤掉的理由。不会因为队列另一份奖励含同名牌而把这张当无效奖励。

## 8. 同名Bonus、消耗副本与升级

[用户确定] 可重复出现、领取、库存，也可放在同一对象；追加同名Bonus按1/3效果。保留合法槽位及每次装配消耗一份副本。

[建议实现] 首份100%，以后每份33⅓%，不是100%→33%→11%。同宿主同Bonus合成强度：`w=1+(n-1)/3`。不同宿主各自第一份100%。不再沿用每Block终身仅一次部署的旧限制。

同名同宿主数值先合成再进总Modifier管线：加值`a*w`；乘数`m`按`1+(m-1)*w`，再与其他不同来源按统一管线计算。正负成本一起按此缩放，不让副作用免费消失。结果触到资源非负/比例区间时明确cap并给出解释。

例如+30%重复三份=+50%；输出×2重复三份=×2.6667。后者不是输出×1.6667，也不是2×2×2。

**不是所有Rule能分成1/3。** 布尔、关系资格、结构开关、加槽、不可重复Field网络采用显式策略：幂等或作者专门定义。纯结构重复卡允许储存，但在无新增效果时不默默消耗副本；UI说明不能叠什么。配方/转换仅缩放明确的数值强度，不复制整条无限链。负向倍数不能无上限变成负消耗。

未获用户确认的“同宿主最多3份”不写成全局硬规则。建筑受实体槽位数约束，Block/组织若需叠层上限须逐卡声明。升级也不能绕过槽位、适用对象、互斥与部署尺度。

[用户确定] 允许方案有两次升级。[建议实现] `基础→改良I→改良II`，本Block蓝图级；影响已装/库存/将来获得的同名副本，不跨局永久继承。升级不消耗另一个同名副本，来源是主题研究奖励。先做内容表列出的12张；其余保持基础版。

影响同名重复效率的Bonus保留扩展语法，本轮只预留可配置系数，不因此再强加一套复制经济。纯结构牌无意义重复应在候选详情标明。

## 9. Commission：方向而非施工清单

[用户确定] Commission是当前Block主题，不是领取普通卡的唯一门票。主题内小目标/事件给extra奖励；最终完成让DT归零时具备主题建筑资格。

[初值] 首发5主题：工业基地、安居计划、商业引擎、港务枢纽、粮食腹地。每主题3阶段“立足/成形/证明”，每主题3事件。表中阈值是内容初稿，不是已通过平衡验收。

条件关注实际供给、已服务人口、实际交付/交易和资源代价，不强制指定建筑数或装某套Bonus。主题限时事件可以有期限，但不会成为全Block的硬回合寿命。

年度卡不要求主题完成。主题M1定向普通牌，M2/M3以升级已有主题Bonus为主要高级奖励；无可升级项时给定向Copy。暂不做SSR稀有度、多选多拿等整套系统。

### 稀有重铸

[用户确定] 变更Commission必须先获得稀有重铸奖励，且使用付代价；不是常驻免费服务。

[初值] Token1份+7.5DT（等价半年额外时间预算）+放弃未完成进度。这个DT费用是直接消耗预算，不推进半年日历，不产生年度卡。来源初值：至少第1年后大周期机会中低权重出现，5年通常0–1份；不作保底。权重在内容里定义，不按每帧掷骰。

已领奖励保留，已入队奖励保留；旧未决事件默认取消不扣后果。稳定里程碑ID防止切回重复发奖。新主题期间累计的生产/交付从切换时快照开始；当前城市状态阈值允许按当前状态判定，不强迫玩家拆掉重建以“清零”。

[建议实现] 本Beta完成主题后不再重铸，简化最终功能定位；此为设计默认而非用户明确禁止。若将来允许，必须另定多已完成主题的最终奖励选择，不能重复领地标。

## 10. DT归零、命名、条件性定型建筑

[用户确定] DT**首次实际归零**：人人解锁命名；只有此前或最后同段已完成Commission，才额外获得相关奖励建筑。归零以后继续×1才完成主题，不追补这一耗尽时点的奖励资格。

资格一旦定格持久保存。名字可稍后输入，奖励可以稍后放，反复开菜单/读档不重复领取。命名不写Trait；功能区身份是`function_role`与奖励来源字段，不能混成地形先天Trait。

[用户确定] 这版奖励建筑先只给数值。5主题对应工会总部、管委会、商会、港务局、农业合作社总部。数值写在内容表，Rule仍走现有明确来源的Block效果；不实现政治制度、跨区组织关系或Tier4。

[建议实现] 奖励以“正式挂牌/落成”立即出现，不再要求DT归零后等数月施工。为满图留预定地标位置或既有市政节点，不强迫玩家拆掉构筑才能领奖。具体位置方案由Codex在现有地图里给出最小改动，并截图验收。

可以继续×1经营，也可自愿结算：保存只读本局记录、名称、主题、建城历时、DT开销、Bonus/升级、人口/经济、定型建筑和重要事件，再独立重开。不传资源、不传卡、不增加下一局强度。不主动做多城可切换存档管理。

## 11. UI作为同版交付

不是等时间机制做完以后贴皮肤。加速控制、现实风险倒计时、年度选择、委任重铸和归零收尾与核心同时交付。

信息注意力层L0–L3与菜单深度是不同维度：L0生存仪表、L1态势、L2情境操作、L3管理研究；L3内部仍可按总览→管理→来源逐层展开。不能把“L3允许表格”误解成每次点预算就全屏长表。

保留工业黄/商业蓝等领域识别，但领域色不是槽型，也不是告警级别。主按钮只有一个视觉重点；不是每个面板只剩一个可用动作。

## 12. 首要验收

玩家能先准备库存和产能，再有意识地烧DT；时间推进后能看懂城市变化，并在年度/人口/主题奖励之后想到下一步。技术检查与玩法反馈分开，不能用运行路线通过证明“已经好玩”。
