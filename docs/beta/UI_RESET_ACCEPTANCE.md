# MET 0.5.0-beta.2：界面与地图重置验收

本轮延续 Beta.1 玩法，实现[四层界面与地图合同](UI_RESET.md)。平台基准为原生桌面全屏 **1920×1080**；依用户要求，没有测试不同大小窗口，没有开展移动端工作。

## 交付行为

| 层次 | 当前行为 |
| --- | --- |
| L0 | 常驻 DT、人口、粮食、时间控制；预算和其他物资明细进入档案 |
| L1 | 最多两条严重警报和额外计数、一张已选主题卡、当前图层图例；可定位实际问题来源 |
| L2 | 选中建筑后显示大图、最多三个图形指标、一个主动作；按居住、生产、服务、货运、施工、暂停和异常区分 |
| 选址 | 地图气泡避开选中地格，最多两项预测、一行成本和投标入口；完整比较在 L3 |
| L3 | 先用概况、关系、比较和阶段引导操作，再展开完整来源；保留槽位、许可、成长、供人优先级、暂停、拆除、市场及政策入口 |

主题奖励入口说明队列中的前序奖励，按核心 FIFO 规则处理后进入主题奖励。不能越序领取，也不会因页面偏好隐藏前序奖励。主动命令失败的原因在短时提示中可见，不因工作台刷新而丢失；自动蓝色城市消息仍进入档案。

图形不是新模拟：宜居使用实际生活收据，缺记录显示未知而非零；服务显示共享服务池的真实容量和使用量，并保留成员来源；施工预计使用同一快照的电力、施工队列和材料条件；暂停、仓储溢出和物资不足分别处理。

## 次级与三级页面

| 页面 | 图形引导与操作 |
| --- | --- |
| 档案入口 | 九个主题卡，图标、当前状态和明确目的地 |
| 财政与资源 | 同单位收入／支出比较，库存容量、实际流向和来源贡献；已有历史与精确账本可展开 |
| 人口与服务 | 住区图像、住房和岗位容量、已启用需求覆盖矩阵；未知记录与真实零值分开 |
| 建筑经营 | 实际投入 → 建筑 → 产出；住户、服务池、运行限制和维护按建筑用途呈现 |
| 槽位与规则 | 运营骨架、已安装实例和合格部署入口；完整 Rule、Field、关系和原始收据按需展开 |
| 成长与施工 | Tier 轨道、升级前后能力对照，失去能力和真实代价可见；共享施工队列与条件明确 |
| 主题与奖励 | 三阶段轨道、真实目标与持续时间；保存的候选横向比较，副本与研究含义分开 |
| 市场 | 三资源买卖报价 → 数量／限价 → 确认订单；实际成交与负价现金方向可核对 |
| 政策与尾声 | 同槽制度并列、当前城市预演；命名、定型建筑资格与归档步骤明确 |
| 城市留念 | 保存的人口、财政与 DT 开销先呈现，主题阶段、定型建筑与构筑分组；最近历史可展开 |

所有管理页面打开时城市暂停。市场参数不会因在线结算刷新而丢失；订单只有点击最终确认才提交。未提交预览的返回、取消和查看来源不改变城市状态或随机流；取消已提交订单仍执行实际市场命令。政策说明中的旧“每小时”只在展示层转换成当前“每来生月”，原始规则保持原值。

时间控制器在更新时同步 DT 数字、预算条和说明，打开尾声页后立即显示当前余额。城市留念读取保存时的数据，不用当前城市的状态替旧城重算；未知旧记录字段显示“未保存”。

## 地图与资产

地图改用明确六角地格、地貌色块和真实 Trait 符号，山林采用原创程序形状，水体保留连续河岸。21 个建筑节点继续复用原有资产，按可见轮廓统一呈现尺度并保留 Tier 区别；庭院、细路和稀疏附房为跨格发展留出空间。

本轮没有逐栋重建 21 套模型，也没有把参考游戏的资产放入项目。附属视觉不创建模拟实体、不消费游戏随机流。地图点击、选择与气泡使用同一投影；原资源、槽位和建筑身份不变。

前后地图分别保留 2／12／53 栋原生截图。同一截图脚本、种子 `905003`、建筑数、地貌签名、镜头与 1920×1080 帧缓冲均经元数据校验。这是明确构造的规模场景，不是自然经营路线；早期尺寸错误或草稿截图未进入正式对照。

## 验证结果

最终主界面与档案全流程运行 **977／977** 项通过，包含 **154 次鼠标或键盘输入、57 张 1920×1080 原图**。产品与测试源码前后指纹相同：`364f2eb7310f6cf297ff21353ad9d7a70578f852e18a6546b5cc4b7d55bb8972`。检查覆盖四层准入、21 个建筑资产与地图命中、主动作和详情、全部城市档案入口、前序和主题奖励依次领取、警报定位、选址气泡避让、精确停止补交、只读快照，以及空名称失败时的可见原因和城市状态不变。

档案流程额外检查真实政策预演、完整 Rule／Field／活动收据、奖励候选的首屏操作、报价数字的单行布局、键盘输入在页面暂停期间保留、订单预览与提交、取消、负价买卖的实际成交和通货变动，以及一次安装准确消耗一份副本。

独立档案专项 **391／391** 项通过，包含 **111 次原生输入、40 张全屏原图**，与全流程使用相同源码指纹。两项套件分开保存结果，部分流程重叠；不是 1,368 个互不重复的功能或真人操作样本。

正常主场景的 Beta 回归 **78／78** 项通过，包含 **5 次原生指针输入、20 张全屏原图**；启动命令没有 `--fullscreen`、`--resolution` 等显示覆盖参数，实际默认启动与后续窗口均为 1920×1080 全屏。检查保存记录的实际指标、构筑与最近 20 条历史、页面返回、城市状态与随机流不变，以及打开尾声时 DT 数字与预算条立即同步为零。引擎运行错误为空，源码指纹与上述两项相同。

核心玩法 **401／401** 项、**6／6** 条完整玩家命令经营路线通过；地图空间与缓存 **38／38** 项通过。核心报告保存 25 个模拟器源码文件的 SHA-256，并已核对与最终实现一致。

已目视复核城市总览、生产与服务卡、暂停／异常、施工、就地选址、运营商比较、财政、人口需求矩阵、升级、市场确认、奖励比较、建筑来源档案、城市留念、尾声和命名错误提示。诊断发现并修复了主题奖励越序入口、命令错误被隐藏、报价数字挤成多行和奖励操作藏在滚动区域下方；诊断运行不混入最终通过计数。先前用户认可主界面时的 650 项记录单独保留，不冒充最终 L3 验收。

## 性能口径更正

复核发现 Beta.1 性能脚本独立构造 App 时漏设 `main.tscn` 的根锚点，实际没有绘出城市地图。旧报告保留其历史意义，并在[原报告](PERFORMANCE.md)与[Beta.1 验收](ACCEPTANCE.md)开头明确更正；旧帧数不作为完整地图性能基线。

本轮使用同一修正脚本，对旧源码包和当前实现重测。新增实际窗口、根节点、App、Map 尺寸和全屏模式检查，地图绘制回调与截图像素检查，以及整个测试期间的源码指纹检查。无效探针运行单独留作诊断，不进入前后性能表。

最终两次运行均通过，源码稳定、窗口／根节点／地图均为全屏 1920×1080。每阶段采样 20 秒，进程串行隔离；推进阶段的完整帧耗时如下：

| 建筑数 | 旧版 p95 ms | 本版 p95 ms |
| ---: | ---: | ---: |
| 2 | 130.63 | 59.92 |
| 12 | 175.46 | 96.25 |
| 53 | 506.86 | 393.07 |

这是一组 Linux llvmpipe 软件渲染对照，未做统计重复，也不能证明目标硬件稳定 30 FPS。模拟器算法源码保持不变；结算回调的差异包含绘制竞争与调度影响，不宣称已优化模拟算法。完整静止／平移／缩放／推进数据、结算 CPU、停止补交与时钟守恒见证据包 `performance/REPORT.md` 和两份原始 JSON。

## 证据与复现

- [构建与测试命令](BUILD_AND_TEST.md)：核心路线、1080p 原生 UI、性能及独立解包。
- `tools/test_ui_reset.sh`：真实鼠标/键盘进入 Control 树，保存源码前后指纹、检查、输入轨迹及原生截图；`MET_UI_SUITE=desk` 单独运行档案专项。
- `tools/build_ui_reset_gallery.py`：从已通过且源码稳定的 UI 报告，以及同场景地图原图生成独立 HTML 对照；不修改图片。
- 源码 ZIP 与证据 ZIP 分开，提供 SHA-256 和成员清单；不收集玩家默认存档、缓存或密钥。旧 Beta.1 交付包保留原名与校验值。

原生检查运行在 Linux X11／Xvfb、Godot 4.7.2、llvmpipe 软件渲染。自动夹具和按钮检查不等于真人试玩；“三秒读懂”的体验目标仍需真人确认。没有声称 macOS／Windows GPU 实机性能通过，也没有声称所有场景稳定 30 FPS。源码与导出配置已更新，不把旧安装包重命名为新版本。
