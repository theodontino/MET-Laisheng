# MET 0.3.2 · 城市工作台

版本：`0.3.2-citydesk.1` · 日期：2026-09-27。

这是在 **0.3.1 城市构筑**上直接更新的同一个 Godot 游戏。保留十类基础建筑、40张方案、8个运营商、12项政策、原有经济参数和城市成果。不增加升级树、垃圾链、跨区物流或另一条产品线。

## 打开与旧城

解压 `MET_0.3.2_CityDesk_macOS.zip`，打开 **MET City Desk.app**。包含 Apple Silicon / Intel 双架构 Godot 4.7.2 运行时，无需安装Python、模型或Godot。

**Mac真机启动、Retina、真实触控板以及手机硬件尚未验收；没有Developer ID公证。** 本轮实际运行检查在Linux同版本原生Godot完成，Mac包另做资源及代码页离线校验；这不等于Apple codesign / Gatekeeper认证。遇到拦截或损坏提示请保留原文，不要关闭系统全局安全保护或SIP。

新版独立目录为 `MET-RiverValley-032`，城市仍为 `river_valley_v4.json`（schema4），显示设置为 `display032.json`。首次启动优先查找0.3.1，再查0.3.0、0.2.1；也可从设置导入存档。复制并校验，不覆盖旧文件；居民、就业、库存、预算、DT、槽位、已装卡、原提供方、当前签约方和已有报价均保留。回退请启动原版本及其原存档，不把新版文件反向覆盖旧档。

## 新的空间分工

| 区域 / 入口 | 点击后的实际功能 |
|---|---|
| 左上「预算」 | 全屏预算与收支，收入/支出、收支平衡、来源、真实历史曲线、余额与一次性支付 |
| 左上「人口」 | 住房与就业联合图层，以及总体人口表；需求覆盖可再展开 |
| 「政策」 | 所有五类制度、12项选项在同一全屏滚动页，无类别分页 |
| 右上时间区 | DT详情、设备系统时间、城镇时间、暂停与推进；主要按钮显示预计DT |
| 右侧任务栏 | 当前任务摘要，可折叠；点击进入任务的进度、解法、放弃与历史 |
| 右下物资 | 粮食、材料、制成品、电力均可直接点开对应详情 |
| 左下建设 | 保留居住/生产/商业/公共四组与现有卡片工作流 |

选中建筑或比较方案时，任务栏缩为入口，不与右侧详情互相盖住。窄横屏将时间和物资控件移至剩余可用地图区域，完整功能仍可由紧凑入口打开；不是把桌面面板等比缩小。

## 物资：一点击就查来源

右下每项资源打开自己的页面，并切换到对应地图分析层。显示库存、产出、消耗、弃置、来源、去向和仓储；电力按即时供需显示，不冒充可储存物资。关闭后恢复原图层。

当前库存和上一个实际周期的产用弃分别标识；没有实际运营数据时，使用明确标注的下一周期预测。不会为了打开详情支付资源或推进城市。地图外市政储备与待安置对象仍计入总量。

## 时间：设备时钟不等于城镇时钟

右上显示设备的本地系统时间（取操作系统时区）和城镇已运行小时数。点击DT打开日期、实时系统秒钟、城镇时间、DT余额、已支付推进DT、下一事件和推进选项。

- **暂停**：停止自然城市结算，也禁止付费快进；系统时钟继续。暂停状态随存档保存。
- **继续**：只解除手动暂停；若仍在查看信息页或比较方案，需退出后才自然运行。
- 信息页及比较工作台有独立暂停状态；关闭它们不会误解除手动暂停。
- 暂停期间不积攒待补算的城市时间，恢复不会突然追赶一段模拟。
- 离线DT恢复沿用原规则；暂停不会导致离线饥荒，也不会修改系统时钟。
- 桌面可用右上0.5/1/3小时推进或「下一变化」；紧凑布局从DT详情进入同样的推进操作。实际按推进时长扣DT，不把预计费用当固定扣款。

空格继续是推进到下一变化的快捷键，但在输入框、信息页、比较或手动暂停时不会误触。P可切换手动暂停，输入文字时不触发。

## 政策：所有制度在同一页

税制、就业分配、环境治理、采购和用地全部列在一张全屏页面中。滚轮、触控板、拖动页面空白、手指滑动都可以滚动。列表只有一个主体滚动区，选择/确认固定在页底。

页面不再常驻粮食、电力、DT等无关资源，只显示当前可能支付的通货和实际费用。选某个选项会调用现有真实内核比较下一周期收支；原政策继续生效，明确点击「采用」后才扣费。当前规则为每次变更16通货；已采用的政策不能重复付费。费用仍由内容数据读取，不新增政策代价。

一次提交一项政策变更，提交后仍留在同一页并保留滚动位置；不是一次浏览后暗中批量更换五项。预算变化或预测过期时重新计算、再次确认。滚动和拖动不会替玩家选卡或收费。

## 预算：余额、持续收支、一次性消费分开

点击预算可看三项主结果：每小时收入、每小时支出、收支平衡。下方是原生绘制的收入/支出曲线（也可切余额）、各项税收与维护来源、最近经营周期和一次性交易记录。

**历史从0.3.2首次实际结算开始记录。** 导入前没有的历史不补造；一开始只有一条或没有样本时明确说明，不画虚假趋势线。实际结算周期、建设/政策/重签等一次性支付、成果奖励、离线DT恢复分开记录。

保留最近720个实际周期（当前0.1h周期下约72本地小时）、最近300条一次性事件与300条任务状态事件。页面先列最近60条，导出记录包含当前保留的完整数据；更早的截断不是未发生。余额可能因奖励跳变，不能拿持续经营净收支误解释所有余额变化。

## 人口：住宅和岗位同时看

点击人口自动进入联合图层：绿色住房轮廓、蓝色岗位标记；选择住宅后显示真实就业连接。右侧总体表包含：人数、住房/待安置、岗位/就业、幸福、健康、教育、需求覆盖、最近周期的每小时人口变化，住区名称可点选定位。

总体状态按人群人数加权，地图外待安置人口计入分母。不能用住宅数量平均，也不能把空房算成已经入住的人口。

「需求覆盖」展开粮食、材料、制成品、电力、医疗、教育、购物、休闲。物资显示满足比例；服务显示实际获得服务的人数和覆盖比例，不把可达范围当作已获名额。尚未启用的需求单列说明，不拿未启用项给居民扣分。总览覆盖是当前已启用各需求满足率的等权平均，再按人口加权，仅是查看用摘要，不新增城市评分或奖励规则。

人口每小时变化来自最近真实周期，另列自然增量和迁入。例如0.1小时内一批6人抵达，会显示该周期迁入折合60人/h，**这不是未来每小时都会迁入60人的预测**。未完成实际周期前显示尚无记录，而不编造0增长。

## 任务：不是只有一个可点的标题

右栏显示当前任务（最多三个摘要，其他从任务中心查看），可收起。任务中心有「进行中 / 当前可接 / 历史任务」。当前接入的是现有四项社区成果：粮食、安顿居民、生活服务、首批生活用品；以及现有三个章节成果方向：宜居、交付、旧区改善（当前只追求一个方向）。

- 放弃需要确认；停止对应奖励判定，不拆建筑、不撤走已拥有资源、不撤回已领奖励。
- 可以从可接任务中有意识地重新接取；城市与原有进度保留，已完成任务不能重复领取。
- 改选章节成果记录为历史，不同时激活三个方向。
- 旧档已经完成的成果保留为「升级前已完成，时间未记录」，不会标成刚完成或再发一次奖励。
- 暂未完成实际周期时，粮食任务不再用默认满足率冒充进度已满。

这不是新的一套Hades房间式随机任务、Bonus许可池、District遗产或建筑升级系统；这些仍是后续设计。0.3.2先把**现有任务、弃接状态和奖励防重**做完整。

## 保留与新增的边界

建筑、方案卡、Slot、运营商、图层、生产/消费、税率、造价、原有成果门槛和奖励数值保留。内容JSON只有版本标识变更。与0.3.1不同的是：新增显式暂停、真实经营历史、任务弃接与奖励资格；因此不能声称所有core模块逐字节未改。

没有新增字体文件；沿用平台可用字体和既有地图素材。没有同步GitHub，也没有新建另一套原型。
