# C｜Slot / Bonus 卡牌组件规范 v1
## MET 0.3.1 · 插槽是容器，卡片是内容

**日期：2026-09-26｜状态：开发规格与HTML交互样稿，不是游戏更新包。**

## 1. 组件关系

```text
Building Inspector
  SlotRack（读取这栋建筑的真实槽形）
    SlotSocket（稳定ID、类型、接受范围、状态）
      空：缺口＋类型名＋征集
      有：BonusCardCompact（实例ID与当前生效状态）

点Socket → 同一地图旁的方案工作台
点Card → 当前卡详情／替换／卸下／重签
```

槽的边框是内凹、稳定、低饱和；卡片有主题色、独立抬高面与插画区。卡装进槽以后，外框的槽类型仍可见，不能被卡面盖掉。

底层继续用当前 `p.slots`、`p.slot_types`、`g.slot_ids()`、`g.slot_type()`。现有结构能表达 `Operations:2`；本轮不为了画卡再迁移经济存档成全新结构。排序使用真实稳定槽ID／既有顺序，不按颜色自动重排。

## 2. 三种卡片密度，共用同一信息模型

| 形式 | 出现位置 | 必有信息 | 不要硬塞 |
|---|---|---|---|
| 插槽缩略卡 | 概况槽架 | 槽符号、短名称/完整可展开、是否已装 | 三条长规则、所有管理按钮 |
| 方案卡 | 投标／方案页／图鉴 | 主题图、名称、槽符号、作用尺度、主要效果、关键代价 | 全部规则源码 |
| 详情卡 | 点开后的工作区 | 全效果、条件、来源、实际/预测、失去的效果、价格、确认 | 与当前动作无关的长历史 |

桌面方案卡建议宽232–280，图像区72–100高；标准效果行至少40高，可多行。名称不能为了统一高度截掉。触摸详情单列，低高度三选摘要仍能切换，确认固定；不把三张长卡同时压进320高。

**风味只一句，属于可选装饰。**数据复杂时先省风味，不省代价。既不要求每张卡专属大图，也不新建随机皮肤系统。

## 3. 卡片的视觉层次

从上到下：

1. 上沿小身份行：槽符号＋“生产/物流/运营”；右侧“建筑/地区/组织”。
2. 主题图片区：复用现有建筑、模块、小图标，背景使用行业纹样。
3. 卡名：醒目且完整；一条窄行业色带连接卡名与主题图。
4. 效果组：图标＋“收益/转换/条件/代价”等短标签＋人话数值。
5. 条件/代价底带：浅暖色，不让整卡变成红卡。
6. 来源行：当前签约运营者徽记；原提供方放展开详情。
7. 局面栏：实际生效／当前未满足／预计变化。仅当有真实来源数据才填写。

卡面颜色表示主题，不表示rarity、强弱或允许装在哪个槽。公共服务卡也能装生产槽，蓝色商业卡也能装物流槽。跨尺度的同一Bonus保持同一主外观，仅改变“建筑/地区/组织”的范围标记与Offer成本。

## 4. 六个真实卡面实例

以下来自当前0.3.0的实际40卡池，不使用上一回复临时编的“公私合营”等示例。

### P01 粗野制造｜工业黄色｜生产

- 收益：**制成品产出×2**。
- 代价：原料、用电各+50%；环境负担+50%。
- 首层不要说“所有物资产出翻倍”：当前rule实际改的是`output.goods`。
- 理论倍率与实测产出分开；缺工时不能承诺翻倍的实际增量。

### P02 研究型医院｜公共服务紫｜生产

- 转换：**30%基础医疗名额→教育名额**。
- 收益：邻接教育建筑效率+20%。
- 条件：名额依然受人员、投入和有限分配约束。
- 只转换一次，不能为了画两行而把医疗再扣一次。体现换职能，不自动标“纯收益”。

### L01 电商仓储店｜商业蓝｜物流

- 服务衰减降低30%；仓容+50%。
- 与工业的既有协同×2。
- 代价：休闲名额归零。
- 不写成“服务半径+30%”，也不把没有的基础邻接加成凭空翻倍。

### P06 高级回收｜设施青｜生产

- 转换：**10污染额度→3材料＋3制成品**。
- 每小时最多处理10；受本格真实可用额度限制。
- 代价：维护+50%。
- 一次消耗共同产出两种东西；不能写成两个各吃10的配方。
- 有卡但没污染时显示“本周期无可处理污染”，不是“非法方案”，因为未来仍可能有用。

### O03 密集住宅｜居住绿｜运营

- 住房容量+75%。
- 每人维护−15%。
- 代价：污染和服务缺口的负面影响+25%。
- 不把“每人维护”缩写成“建筑维护下降”，不把空位当人口立即增加。

### M01 模块化设计｜通用灰青｜运营

- 增加1个可装生产或物流的弹性位。
- 代价：维护+25%。
- 弹性位的外框标“来自模块化设计”；里面仍有卡时，卸下父卡前说明依赖。
- 不增加一个人人都有的第四槽，不把Flex画成新专业类型。

## 5. 40张卡的映射，不再维护两套经济数值

`config/bonus_card_catalog031.json`逐项保留：当前ID/中文名、允许Host/Slot、资格Trait、原summary、完整rules_reference、主题、图片、简述和规则引用。全部40个ID与当前源码核对，未实现脑暴项不加入可选卡池。

其中18张常用/易误读卡给了细化展示行；其余沿用当前player_highlights并保留全部规则详情，不把中性句子自动判成收益或代价。

接入时，数值应尽量由对应Rule或运行时值格式化。JSON中的展示副本须以规则哈希核对，内容改版时失败提示，不能悄悄沿用旧百分比。完整数据只用于解释，UI绝不执行这里复制的一组rules_reference。

新的 `visual_domain` 只是渲染元数据，不添加到BuildingTrait或Bonus资格里。图鉴中的默认Host为空，只有真实实例/投标上下文才显示provider、contract和价格。

## 6. 插槽状态要做全

| 状态 | 外观 | 点击结果 |
|---|---|---|
| 空闲 | 虚线内凹框、类型缺口、加号 | 征集现有规则允许的方案 |
| 已装并生效 | 实线框、卡面、轻微勾标 | 看当前贡献和替换操作 |
| 已装但无当前收益 | 保留卡色，角标“条件未满足” | 看原因；不强制卸下、不自动红警 |
| 可替换 | 原卡留在槽中，新卡浮在工作台 | 看失去/获得效果，确认才替换 |
| 施工/暂不可改 | 中性锁纹，具体原因 | 可阅读，不可提交；不靠颜色猜 |
| 弹性子槽 | 双缺口、允许类型、父来源 | 装允许类型，展示父子依赖 |
| 拆父卡被阻断 | 依赖提示和子槽定位 | 返回处理子卡，不静默删除 |
| 请求/预测更新中 | 小状态标记，旧值淡化 | 禁用过期确认；不显示零收益 |

### 界面选择状态与经济生效状态分离

“卡被点中”只是预览；“卡已装载”是游戏状态；“当前有效果”是本周期结果。三者不能共用一个绿色边框。选中用外焦点框，已装用固定小标，条件不满足单独说明。

## 7. 装配流程：点击优先，拖拽不做必需条件

空槽 → 征集候选 → 同地图比较 → 明确确认采用。已有槽 → 看原卡 → 征集替换 → 显示旧卡损失与新卡收益 → 确认。

拖卡只是将来可选捷径。0.3.1必须保留点选+确认，手机、键盘不依赖拖放。鼠标移出卡片不会丢掉当前候选；滑动列表不能安装卡。

重签保留原`provider_org`，修改当前`contract_org`，同源奖励看当前合同与`operator_org`；同源显示“自营”而非“纯血”。不画进度把它伪装成最重要目标：+3%是现行小奖励，混搭始终合法。

多个不同Host的Bonus不一定占建筑槽：地区/组织内容使用范围标记，不能为了卡片感强塞到建筑的三槽架里。Policy外观可共享卡体，但固定显示制度槽类别，不当成可搬来插入生产槽的卡。

## 8. 费用、否决与来源

所有价格从现有Offer/API读取。48通货是当前常规方案报价基准，不保证所有候选/尺度同价；重签40通货+1DT、改槽90通货+6材料+1.5DT、换运营者150通货+3DT均由已有动作检查，不新增消费。

不够钱、错槽、资格不满足、父槽依赖是不同原因。无可用候选时说明原因，不生成一张假卡。

最后确认必须重新校验当前预算、选中实例、稳定槽ID、城市版本。保留0.3.0的决策暂停、免费返回和锁定报价；卡牌化不能变成免费洗牌或点击时直接消耗资源。

## 9. 主题感怎么做，不要求40张AI插图

工业用蓝图斜线和车间剪影；商业用檐篷/货架；农业用田垄；公共用院落/书页/医疗图标；居住用窗格；设施用管网。复用0.3.0的主体与模块，主题图控制在卡上部。装饰不画文字、不画虚假的数值徽章、不模仿稀有卡亮金框。

插入反馈120–160ms，减少动态时直接切换。空槽不呼吸闪烁，满配不用持续金光。音效沿用既有轻量cue，不叠一套强刺激奖励系统。
