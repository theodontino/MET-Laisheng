## 存储和更新原则

- 仍是单线程、分阶段计算。可运行上限与回补是统一分配规则，不靠字典遍历抢资源。
- 数值在Tick/序列化边界按1e-6精度归一，修复同引擎JSON小数最后位引起的续跑分歧。不是改成全整数引擎，也不宣称跨OS位级一致。
- slots使用「稳定slot_id → bonus_instance」与slot_types映射，支持同类多槽。等价实现计划的有身份槽结构；不因为逻辑类型改变而重命名或丢弃实例。
- provider_org保留原来源，重签只新增contract_org。自营查询优先合同，再回退原来源。
- preview_mode只在副本中求值，不发生迁入/安置/成就奖励；预测假设明确显示。缓存依赖revision、tick、项目数、目标和报价。
- 旧仓存保护存在legacy_storage_floor中，随原库存被消耗递减；不会变成永久额外仓容。
- 没有改掉Field的来源身份，也没有新增专属套装开关。原通用规则继续决定产业/服务组合。
