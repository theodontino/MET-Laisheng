# A｜UI 视觉分层规范 v1
## MET 0.3.1 · 用颜色认主题，用轮廓认操作

**日期：2026-09-26｜基线：0.3.0-cityview.1｜状态：开发规格，尚未接入游戏。**

这次只修改当前 MET 的信息组织、卡片与控件表现。不改经济、不加资源、不改变槽位权限、不重做地图，不生成另一条游戏产品线。配套 HTML 是这些界面组件的交互说明书，不是玩法原型或可运行的新版本。

## 1. 这轮必须改掉什么

用户截图中，住房人数、三项状态、消耗、运行结论、三个槽与拆除按钮都是同一个纵向列表。现有 `W.section()` 只添一行金色文字，并没有把它下面的内容组成独立区域。给每段再加标题不能解决归属问题。

本轮要同时实现三种区分：

| 玩家要辨认 | 主编码 | 辅助编码 | 禁止替代 |
|---|---|---|---|
| 这是什么主题／功能 | 卡面色带、建筑身份条 | 图标、中文类别 | 把颜色当作装配资格 |
| 这是什么操作对象 | 插槽凹框／卡牌凸面／普通按钮／折叠行 | 类型图标、动作词 | 所有东西都画成等宽大按钮 |
| 现在是什么状态 | 独立状态徽记、边缘标记 | 文字、符号、纹理 | 用整张卡变红表达一条代价 |

**行业色、槽类型、状态色是三套语义，不共用一个“type_color”。**

## 2. 五级信息秩序

| 层级 | 解决的问题 | 视觉与交互规范 |
|---|---|---|
| L1 对象身份 | 我正在看谁 | 24字号标题，80–96主体缩略图，类别色条；标题区固定不跟正文滚走 |
| L2 关键结果 | 它实际做了什么 | 白色主结果卡；28号主数字；同一结果旁放单位、分母；同卡只讲一种结果 |
| L3 当前状态与动作 | 是否需要处理，怎么处理 | 有真实问题才出现告警条；一个明显主动作；正常状态降为小徽记 |
| L4 装配与解释 | 怎么配置，为什么如此 | 槽架与卡片；完整账目进入可展开详情；不能把关键代价藏入工具提示 |
| L5 管理边界 | 暂停、运营者、拆除 | 更多菜单或明确管理区；暂停中性，拆除危险；不与“采用”并排同权 |

固定头部＋单个正文滚动区＋固定上下文操作栏。不要套三层滚动。标题区域的界线、内容区域的间距、卡片的内部子组要同时存在，不能只靠细分隔线。

## 3. 功能域颜色：行业有性格，正文保持清楚

下面是本次的**展示分类**，不是新增建筑类型、Trait、规则权限或建设菜单。

| 视觉主题 | 色带 | 正文强调色 | 浅底 | 用到现有内容 |
|---|---|---|---|---|
| 居住 | `#54A374` | `#22563C` | `#E8F3EB` | 河谷住宅、密集住宅、工厂家属区 |
| 农业 | `#8DA248` | `#485B21` | `#F0F3E1` | 农场、家庭农场、农家乐 |
| 工业 | `#E7AF36` | `#72500B` | `#FFF3D1` | 料场、工业厂、粗野制造 |
| 商业 | `#4A8BCE` | `#245184` | `#E9F2FD` | 市场、电商仓储店、商业改造 |
| 公共服务 | `#9B80C8` | `#654486` | `#F2EBFA` | 医疗、教育、休闲；子类靠图标文字区分 |
| 基础设施 | `#49A8B0` | `#245E65` | `#E5F3F3` | 动力、仓储、配送、供热 |
| 通用 | `#84959C` | `#455860` | `#ECF0F1` | 模块化与跨领域内容 |

亮黄、亮蓝只画色带、插画底纹、图标块，不直接拿来写白底小字。工业卡上是深褐文字与黄色主题区，不是低对比的黄色小字。

卡片使用一个主色族，占顶部或侧边；收益／代价行使用自己的语义标志，不再每一行铺不同大色块。边框颜色不代表稀有度：目前没有足够依据给内容凭空添加蓝紫金品质。

原建造工具仍是“居住／生产／商业／公共”四组。生产组内的农场、动力、工业可以分别带农业／设施／工业视觉色；不要为了配色再给菜单加六个新一级按钮。

## 4. 槽类型：三种，不能从颜色长出第四种

| 引擎类型 | 显示名 | 插口轮廓／图标 | 配色原则 |
|---|---|---|---|
| Production | 生产 | 方形缺口＋生产图标 | 中性结构色 |
| Logistics | 物流 | 六边形缺口＋双向箭头 | 中性结构色 |
| Operations | 运营 | 圆形缺口＋运营图标 | 中性结构色 |
| 已有规则添加的 Flex | 弹性 | 双缺口＋允许类型小符号 | 中性虚线边框；标来源 |

例如：**研究型医院是紫色公共服务卡，但需要“生产”插口。电商仓储店是蓝色商业卡，但需要“物流”插口。**两者不矛盾。相同的插口符号出现在槽架和卡片左上角，提供视觉匹配。

不新增公共服务槽、组织槽、政策槽或“文化槽”。Policy 继续使用 Block 的既有制度槽，Organization 继续是关系对象。所有类型以 `slot_type()`／`allowed_slots` 的真实数据为准。

## 5. 资源、状态、单位的显示系统

使用 `ResourceChip = 图标 + 中文名 + 数值 + 单位`，小范围着色，数值默认深墨色。货币、DT、人口状态与Field虽然也使用这类显示组件，但不会被塞进普通Resource模型。

| 数量 | 强调色 | 显示规则 |
|---|---|---|
| 通货 | 金棕 `#825918` | 钱包余额与“/h”收支分开；不要只有孤立640 |
| DT | 陶橙 `#934B30` | 明写DT，不和通货都画金币 |
| 粮食 | 深绿 `#34652B` | 产／用／弃使用带标签列，不只给净增 |
| 材料 | 棕色 `#76533C` | 图标与文字一起，避免和工业黄混为一义 |
| 制成品 | 钢蓝 `#375677` | 保留当前实际资源ID，不恢复多等级制造品 |
| 电力 | 深金 `#806208` | 当前供给／需求；不默认画库存箱，不重复两条“电力” |
| 人口 | 青灰 `#335D66` | 人数、住房位置、岗位是不同分母 |
| 健康／幸福／教育 | 青绿／莓红／蓝紫 | 三个独立状态格，不在无分隔文本里串起来 |
| 环境负担／余热 | 橄榄／铜色 | 使用当前真实指数或额度，不捏造浓度与温度 |

**合计前不四舍五入。**住宅用电可以汇总为一行“合计”，再展开楼体和住户；作用域不同或周期不同的值不得硬加。同一组结果必须标明“最近周期实际”或“下一周期预计”。空数据是“待结算”，不是0。

## 6. 好坏不是加减号决定的

- 粮食每小时消耗3.2：普通输入，不是红色错误。
- 建筑维护增加50%：代价标记，琥珀图标＋“代价”，卡面行业色不变。
- 污染增加：显示环境负担增加；有回收用途时允许补“可能被利用”，不自动涂绿。
- 原料供应不足：由真实满足率产生警告。
- “投入齐备”：正常徽记，不能沿用当前 `bottleneck` 的红色默认样式。
- 空槽：虚线和加号，属于配置机会，不是必须处理的危险。
- 暂停：中性色与暂停图标；拆除：红色描边＋二次确认，不同等级。

状态值需独立于文案，例如 `status.code = ok / warning / danger / inactive / unknown / conditional`。禁止用“文字里有没有‘缺’字”来选择颜色。

## 7. 组件、字号和密度

主面板纸白底 `#F7F6F0`，主卡白底，槽架浅灰绿凹面，顶栏深青墨。间距统一4/8/12/16/24/32；同组间8–12，组间24。大面板圆角16、卡10、控件7。阴影只用于可拿起的卡和浮层，插槽用内凹对比；表格与正文不加重阴影。

字号：标题24、重要数字28、组标题16加粗、正文16（触摸17）、辅助14。颜色、文字与图标都有可读对比目标；检查脚本实际列出配色比值。字号125%/150%时改用更少列、滚动正文，不缩回小字。

触摸主操作目标48×48逻辑单位，相邻操作间8。这里是本项目设计值，手机真机实际触控尺寸仍须验收。焦点环3，永远可见；键盘、鼠标、触摸共用选中状态。

## 8. 顶栏和建设工具补刀

顶栏金额必须有钱图标／“预算”，现金流有时间单位；居民是“18/24 住房”而不是与目标18/30紧挨又无解释。目标进度和居住容量分组。预算、DT、人口不再一串等重数字。

建设项换为真正 `BuildingTile`：上部缩略图，下部完整名称（允许两行），底部价格行。默认132–152宽、至少144高；点中高亮整张卡。价钱与名称不共用Button的裁剪文本，当前96×78大图挤小字的方案停止沿用。视口窄就少放几列、滚动，不截成“基础”“90通”。

## 9. 与现有图层的边界

医疗／教育等地图图层保持0.3.0原来的来源、容量与实际分配语义。本轮只复用相应图标色，不能把“医疗够得到”画成“居民已被服务”。分析图例的标度独立于行业色，不为了统一把所有公共设施和所有健康结果都涂成同一片紫色。
