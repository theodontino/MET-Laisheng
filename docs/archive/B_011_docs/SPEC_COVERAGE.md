# 当前修订覆盖

| 用户反馈 | 本轮实现 | 边界 |
|---|---|---|
| 没有人口，像卡牌管理 | 每住宅真实住户、住房、就业、生活状态 | 聚合人口，不是个体小人 |
| 资源Tag太多 | food/material/goods统一库存；energy供需 | 建筑/地形Tag保留 |
| 制成品开局直接ban | stage<2不生产、不消费、不显示库存 | stage2仅低级；中高级未做 |
| 商业刷不出、不知用途 | commerce家族和阶段Tag；实际消费覆盖和税收 | 不做动态商品价格 |
| 教育/知识不清楚 | 技能存量/知识流量分开，UI有说明 | 全区技能适配，不做单工人履历 |
| 公园医院不显著 | 有限覆盖、健康幸福变化、可看作用住宅 | 数值体感仍待试玩 |
| 邻接不明显 | 局部噪音/污染、服务连线及来源 | 不做实际交通物流 |
| 区划鸡肋 | 不再涂区，直接圈场地+Tag | 内部类别保留供图形和升级 |
| 农业应抽农场果园牧场 | 两个核心候选来自意图家族，第三可相关惊喜 | 权重/家族映射是薄手工数据 |
| 需求产生内生张力 | 食物、岗位、住房、生活服务、阶段制造供给相互约束 | 可暂停迁入/阶段，非强制无限扩张 |
| 升级应降低解决需求成本 | 省工、复合服务、清洁生产、协作作用 | 两个主升级里程碑仍保留 |
| 托卡马克之冠是City结局 | 不在当前首块解锁/通关条件 | City后期未开发 |

自动化通过只确认规则实施，不能取代用户对内生张力和游戏趣味的验证。
