# 0.2.0 实现与文件入口

## 来源

唯一游戏源码基线为重新上传的 B 0.1.1 人口版。原 B 的各层按既有文件组织原位重构；原代码在Git基线与 `docs/archive/B_011_source` 可查。未使用 C 的 model.gd，未修改远端GitHub。

## 规则与阶段

普通规则不直接修改权威世界。数值与配置先编译为只读统计/选择结果，后续分配器给出申请、收据和覆盖，再写入下一状态。新建筑投产、人口增减、迁居在最后提交。没有在某工厂产出时立刻把产物喂给同Tick下一个工厂的递归链。

6阶段：空间 → 人口/物资/能源分配 → 建筑运行 → 生产仓储 → 环境/服务/人群 → 财政/结构。phase是引擎约束中的固定时机，不能由内容任意插入依赖循环。

内部注册动作包括 modify、configure、capacity_convert、capacity_copy、grant_recipe、field_convert、emit、relate、slot_add，分别落到协议中的数值、转换、场、资格、分配/转向、关系、读取/聚合、槽位变化。复杂分配由通用分配器解释配置，不为“某运营商+某Bonus套装”写专用判定。

同一数值：Base → 加减 → 倍率 → 上下限 → 最终Override；最终覆盖按具体程度、优先级、稳定ID决定。重编译从基础定义开始，不能累计重复添加。

## 当前工程边界

目前单线程执行，按阶段和稳定排序保持结果不随字典遍历顺序改变。**没有执行多线程加速，也未证明不同CPU/操作系统逐位相同。** 同引擎JSON保存恢复及重复运行已验。金额以百万分之一量化避免JSON浮点尾差；其他核心量仍为有序浮点运算，未来要做强跨平台重放可进一步统一数值精度。

缓存/派生字段和权威定义已分开，但本版多数Field每Tick重新求值。更细Dirty缓存、任务池和性能压力评测尚未完成；不宣称未来并行化零改动。

## 对象语义

- 人群保存独立ID、host、count、健康/教育/幸福、效率、需求、就业和服务分配。搬家不按建筑级联删除。拆分/合并保留lineage和加权状态；聚合组ID不是每个个体的终身编号。
- 建筑有独立inventory和storage，operator与Bonus provider是两个不同来源字段。
- 地块保存组合Trait、单建筑引用及Field派生缓存，不解释污染善恶。
- Field由Source实体、类型、强度和传播定义构成；相同来源不同类型分别有ID。Field样本保留来源，聚合只是读操作。
- Trait属于对应实体的先天命名空间；改造通过Label/语义角色使旧工业参与商业规则，不直接篡改原工业Trait。
- Bonus/Policy都是规则容器；实例保留挂载宿主、来源和Active。没有持续几Tick的计时Bonus。
- 准备、拆迁、政策切换是玩家命令的原子边界，不在Tick中间改结构。
