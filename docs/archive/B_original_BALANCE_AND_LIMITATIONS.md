# 0.1.0 临时参数与边界

所有以下数字是这次实施用v0参数，不是重新替用户定最终GDD。

## 参数

共同起点：680通货、22DT、55食物、78材料、18制成品；Origin再加各自家底。基础隐式供给每本地小时食物0.65、材料0.8，能源6。初始仓容食物90/材料260/制成品160，专业项目/协作可改变仓容。

DT容量72；离线0.5DT/现实小时。正常在线本地1:1；只在F8内提供实验倍率。轻负载 `1+0.045×结构规模+0.004×人口容量`；升级/场地规模计入，暂停不消除结构成本。

1～7格项目规模系数 `1+0.13×(格数−1)`，成本、容量、输入、产出、能源等相应放大。不承诺这是最好空间平衡。

里程碑有效运行3h/7h，加邻接运行项目或12材料条件之一；另有1.6倍有效运行时间的可达替代条件。关系3有效协作小时，成长按双方使用率乘积。达标协作95通货+3制成品，暂不采纳可免费搁置。

重招通货18/32/55/85/125/180，之后继续递增；第三次开始叠加DT。关闭面板保留结果；撤回再规划支付当前重招价并继承次数，防止换地免费刷新。无锁牌功能。

治理初始75/75；任一<12或同时<28触发危机，4本地小时复核。140通货+8食物保守修复，或65%成功/35%立即罢免的自愿风险。日常供给与照护影响民心、负现金影响授权。薄版不是完整政治模拟。

三个委托按到任时刻起48/24/36现实小时计时，外部窗口不因退出或DT改变；承诺逾期一次性处罚，未承诺过期无失信。只是承诺不等于需求消失。

首次完成：6个建成运行项目、基础供给稳定1h、1次升级、1次协作、无危机。完成后无限模式不加额外毕业税；原有治理风险仍在。这里不是“至少玩多久”的人为限制。

## 内容与简化（不是隐瞒的完成度）

- 4Origin、20开发Proposal、12升级、4Fusion关系模板（每类2种结果）、6施工机会、1HopeCity+2居民请求、3项科技、1条危机。
- MVP15仍实验：目前一个Site一个机械项目，院落/车棚/小仓库只是视觉；不支持同Site继续新建第二主体。
- 自由定居的首版家底也带固定基础料棚，未单独加“自选首栋Anchor”菜单。起源选择、后续四用途招标仍自由。
- Origin、Survey和地貌只做小表薄揭示。地基/暗泉有少量数值作用，未做详勘或完整自然地质模拟。
- 项目机制由有限操作模板构成；基础生产设施仍有必要的产出数值。没有把每张白卡都做成独有规则引擎。
- 接口库存用同一资源下的签名分桶，UI仍四类。无建筑来源追踪、外部市场、跨Block物流、复杂腐败。
- 本Block普通供给含极小固定安全底座；不是长期外部贸易或跨区馈赠系统。
- 每个建筑两次升级，但共用12条候选，尚无大量手写里程碑。临水/地形/邻接会改属性和权重，不是无条件保证每处都有3个独特方案。
- Fusion成熟后固定模板两种方案打乱展示；不花钱重排完全相同的小池。
- 普通施工无失败骰子，机会是接受/原计划的二选一。危机豪赌才明确有执行风险。
- 没有正式音乐/音效、角色动画资产、图像生成资产；建筑为少数程序化模型族，不是20套精美独立美术。
- 未实现：Life、第二Block开发、产业链同步、跨BlockBuffer、DistrictOverdrive、自治AI/外交/回任、长期Meta、移动端。

## 必须由真人继续验证

Mac启动、系统授权、Retina、触控板缩放/移动、原生导入导出、挂起唤醒与性能；Linux GUI不代替上述验证。

数值稀缺、好卡/坏卡的上下文差异、抽卡频率、关系成长是否只是另一个等待条、治理是否烦人、奖状后是否愿意继续——自动测试均不能证明。

保存是schema1+最近备份，只有损坏检测而非强反作弊。系统时间可人为修改；离线容量与时间回拨只做基本保护，不构建服务器信任体系。重要存档请导出。

## 开发中实际修过的问题

- 关系抽取在资金不足时占用招标，现可免费暂缓，保留关系；不会逼玩家用DT/钱撤回固定两张关系牌。
- 可达的基础制成品生产项目最初要消耗制成品施工，会让库存耗尽的恢复困难；现在基础水磨加工项目不要求制成品，依然消耗钱/材料/时间。
- 多格Site起初只提高价格、没提高规模产出；现对输入、输出、服务、人口、能源等统一应用规模系数。
- 重招不能只是收费洗顺序；小池耗尽不会收费，重招至少保留一个新候选。
- 升级不能追溯把旧库存变高级；已加入回归测试。

## 关于16条流程结果

原简陋启发式在16条中有2条没完成：一条不重试之前未付得起的协作，另一条把公共设施建在没有兼容邻接的位置。保留`playthroughs-naive-baseline.json`。没有因此取消邻接/资源约束；改进测试玩家，让它按公开Tag选择位置、重试待采纳关系后，同16条均走通，无资源注入或自然长等待。

这说明这两种测试策略的结果，不证明任意选择都不会软锁，也不证明16个人会觉得好玩。
